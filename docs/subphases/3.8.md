## Design

- The interpreter and every opcode handler are translated label for label, and they run on the
  emulated CPU's registers and stack. Every register, every memory byte and every stack word below SP
  (CALL return addresses, PUSHes, INT 0 frames) ends as the original leaves it. Handlers are
  dispatched by the handler address read from the table at DS:3204, so the table stays authoritative.
- **Callees.** Routines another area replaces (world_to_eye_delta, rotate_point, the outcodes, the
  clip steps, project_dot/_regs, draw_line, draw_horizon_list, build_view_matrix, clear_view_buffer)
  are called through their `NativeEntry.fn`, found by address in the area tables via `areas.h`
  (read-only), after an emulated CALL. The native's `.cycles` is charged. Routines with no native
  (atis_start 4FBF, cga_program_regs 5600), and any native turned off with `--native-off`, run as
  original code with hooks off until they return.
- **Hand-over to original code.** Opcodes 03, 0F and 42, the unassigned opcodes, opcodes > 42h, an
  unknown `jump_if` or shift-table target, a foreign INT 0 vector, and the world_to_eye_delta "point at
  the eye" hang all leave the CPU exactly where the original would be (via `longjmp`) and return
  without the RET. The game then continues, and hangs, in original code. No behaviour is invented.
- **INT 0.** IDIV/DIV overflow and divide by zero in the projection (4D18/4D56) and in the segment
  setup (43F4/4402/4410) are emulated: FLAGS/CS/IP are pushed, with FLAGS computed as the emulator
  would, and the game's handler 4DC6 is applied (AX = ±7FFF by the sign of DX^BX).
- **Polygons.** 2F/2D, `poly_fill` 549B and the span fill 59B7 (scratch word 0C0C:1F40) are translated
  in full. The edge path at 5060 is 3.4's rasteriser, called through draw_line.
- **Cycles.** Each translated instruction adds what cpu8086.c charges for it; the entries' `.cycles`
  (20) is the final RET. I checked this with a temporary instrument (not committed) that ran the
  callees as original code: native and original cycles were equal on **every** call of the 14 campaign
  sessions and of the area sessions below. With natives on, the only drift comes from the callees'
  fixed `.cycles` (e.g. draw_line's 1400).

## Coverage beyond the campaign (areas 1–4, radios, SPLASH)

`tools/trace_campaign.py` is unchanged. I ran these sessions with
`--verify scenery_interp --verify draw_scenery --verify scenery_reset_ip`; all gave 0 mismatches.
They start with `120:A,180:B`. Editor rows: **North = field 10, East = 11, Altitude = 12**. Rows 8 and 9
are the blank line and the "Aircraft Position" heading, so `trace_campaign.py`'s "altitude = field 10"
actually sets North. Each value is set with its own editor visit: Esc, Enter ×field, digits, Enter,
Esc, with 20 frames between keys. Editor value = 16384 + position unit.

| Session | Position (N, E), editor values | Then |
|---|---|---|
| area1 LA | -1235, -10640 (15149, 5744) | alt 0 / 1500, F2, Keypad 4/6/8/2, Numlock radar on/off, `=` zoom; about 3500 frames |
| area2 Seattle | 4967, -9772 (21351, 6612) | same |
| area3 New York | 650, 4681 (17034, 21065) | same |
| area4 WWI | 1024, -8960 (17408, 7424) | same |
| radio_meigs | Meigs start | `C`, `-`×3, `C C` (6 frames apart: decimals), `-`×11 → COM 121.30 (Meigs ATIS); `N`, `=`×3, `N N`, `-`×2 → NAV 113.90 |
| splash | N 786, E 290/293/296, alt 0 | SPLASH crash code 08 (water pixel test) taken |

In all four areas `[03BE]` was confirmed as the area number. The NAV and COM match paths (station copy,
ATIS start) and the SPLASH write ran and verified.

**Not exercised by any run.** These are straight translations:
- the opcodes no program uses: 05, 06, 08, 0D, 0E, 10, 11, 15 (as an opcode), 2A, 34
- `jump_if` true
- the 4234 overflow branches
- clip-step exhaustion
- two poly_fill neighbour branches (5555, 5592)

I started a synthetic test program (written into area 0's dead block 51FB) for the unused opcodes, but
the original itself did not return within the 5M-step verify cap on it, so I dropped it unfinished.
