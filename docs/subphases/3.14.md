- **Cycles.** A temporary check in `verify_call` (not committed) compared each native's charged

- **Screenshots.** Every 600 frames, these seven natives on vs `--native-off`, in all 14 campaign

### How the cycles are charged

`flight_motion_cycles.h` lists the cost of every original instruction in these routines and their
helpers under the `cpu8086.c` model. For a conditional jump or LOOP, it gives both the fall-through
and the taken cost. A scratch harness generated the table: it linked `cpu8086.c` and single-stepped
each instruction from `extracted/boot_mem.bin` under several flag and register settings. The C code
mirrors the original's paths:
- `run(from, to)` adds the instructions in a straight run.
- `taken(addr)` adds the extra cost when a jump is taken.
- `sincos` and `div_q15` costs come from 3.1.

The `.cycles` of each entry is 1, and the native adds the rest.

### Interrupts: handing a call back to the original

The original routines run with interrupts enabled. The timer handler changes state that these
routines read between instructions: `flight_forces` writes turn rate, airspeed, pitch and more, and
the keyboard handler changes the controls. A native holds interrupts until it returns.

With bit-exact natives and exact cycles, the demo's screenshots still diverged after about a minute.
The cause was a timer interrupt landing in the middle of `flight_integrate` (about 3,500 cycles,
against a timer period of about 16,000 to 24,000 cycles).

The natives now check this. Every native memory write goes through a small undo log. At the end, if
either of these would happen within the routine's cycles, the native undoes its writes, performs
the routine's first instruction, and continues the CPU in the original after it
(`irq_hand_back`, `continue_original`):
- PIT channel 0 would reach zero
- the keyboard would deliver a scancode

That call then behaves exactly like the original, interrupts included. This is what makes the
screenshots identical. The hand-back happens on roughly the fraction cycles / timer period of calls:
about 1 in 5 for `flight_integrate`, and much less for the others.

Two paths always run as original code. Their busy-wait loops run for seconds with the timer live:
- **crash message:** `crash_handler` with `crash_code` set: 65535 × 3 MUL, about 3 s
- **engine starter:** the `engine_update` path through 2D55: 65000 MUL, about 1.2 s, then
  `sub_0A19`, which redraws the panel text

Under `--verify`, the original also runs without interrupts. There, the natives never hand back, and
these two paths run the original routine inside the native, single-stepped with natives off. The
verifier detects this through `cpu.write_log`, which is only set during a verify run. These paths are
therefore verified as "native = original". There is no C transliteration of them to compare.

**Framework suggestion (for the coordinator).** Other long natives that read state changed by an
interrupt handler (the 3.13 forces run inside the handler; scenery and panel routines are long) can
cause the same replay drift. A shared "an IRQ is due within N cycles" helper in `native.h` would let
them use the same hand-back.

## Findings

### flight_integrate (1906)

Per frame:
- **Time step.** `dt` = (tick18:pit_accum − previous) >> 5 (arithmetic shift, 32-bit), into
  `frame_dt` [086A]. The previous value is kept in 0896/0898.
- **Turn and distance.** heading += turn_rate × dt (Q15). Distance [086C] = dt × airspeed.
- **Track.** track = heading + hi([08A2] × [089C]). This is a plain IMUL without the Q15 shift: a
  crab or sideslip term. sin and cos of the track go to [089E] and [0846].
- **Steps.**
  - horizontal [0842] = cos_pitch [0840] × distance
  - east [0860] = sin(track) × horizontal
  - north [0894] = cos(track) × horizontal
  - climb [0830] = sin_pitch [089A] × distance
- **Roll.** roll_rate = [0890] (1/roll inertia, from `flight_params`) × roll moment [0892] (from
  `flight_forces`). bank += roll_rate × distance × 4.
- **Position and altitude.** pos_north, pos_east and altitude are 32-bit and get the steps
  sign-extended. A negative altitude is clamped to 00000300h (3.0, ground level).
- **Altitude reset.** While [08F9] (set to 0C by `editor_apply_state`) is non-zero, `sub_3C9F`
  re-applies the editor altitude: (feet + 9) × 4E0Ch >> 16 − [0906], at least 3. On the ground it
  brakes (`key_period_brakes`) instead of running the landing checks.
- **View pitch.** view_pitch = 0300h − pitch + [083A] + flaps term [0868] (only when airborne on the
  previous frame) + touchdown kick [088A].
  - **Original bug, kept.** The code loads DX = angle_of_attack, then `IMUL [08C6]` multiplies AX,
    so DX is ignored. AX holds whatever the integration left there: the climb step, 0300h, or the
    low word of `sub_3C9F`'s MUL. [083A] = hi(AX × [08C6]).
- **On ground.** The aircraft is on the ground when the 24-bit altitude at 30D5..30D7 is below
  000301h.
- **On the ground.** bank = roll_rate = 0, and a negative pitch is set to 0. Then the landing checks:
  - Gear up sets crash_code 0A. It is not final: the checks below can override it with 04.
  - If vertical_speed's high byte is < −6, i.e. sinking faster than 0600h, crash_code = 04 and
    the routine returns.
  - If the sink is gentler and |view_bank high byte| ≥ 0A (about 14°), crash_code = 04.
- **Touchdown.** On touchdown (on_ground changed): sound_state = 8 and [088A] = vs_high << 9. Each
  later frame sets [088A] = 0.
- **Lift-off.** On the first airborne frame, if (pos_north+1) & 7 = 0, then
  [1E22] = ((pos_north+1 + pos_east+1) & FF) − 80h.

### flight_params (1AF7)

Every 4th frame (phase 2). It returns at once in slew mode.
- **Air density** = 7FFFh − 5 × [0900] (displayed altitude).
- **Weight** = [08EE] (empty weight, 09C4h) + [08B6].
- **Mass terms.** [088C], [088E] and [0890] = div_q15 of the constants [08C0] 0329h, [08C2] 02BCh and
  [08C4] 2EE0h by the weight. [0890] is the roll term used above.
- **Vertical speed** = airspeed × sin_pitch.
- **Self-levelling.** If the rudder's high byte is 0, a non-zero bank moves toward 0 by
  [08D8] = −14h (right bank) or [08D6] = +14h (left bank). It is clamped at 0 when it overshoots.
- **War-mode re-arm.** When [0406] ≠ 0 and airspeed = 0:
  - `sub_1BB0` repairs the magnetos and refuels to 23h per tank. It also clears the engine faults,
    sets the oil temperature rate to 3, resets the panel masks and marks the 6 enemy records.
  - With [0406] = 2 it also sets ammo to 65h (and decrements it through `war_ammo_dec`, which writes
    3 ASCII digits to 1ED3) and bombs to '5'.

  [0406] is then cleared. Nothing in the traces writes a non-zero value to [0406].

### slew_update (1C35)

- **First slew frame** ([08F6] = 1): elevator, rudder and aileron are set to 0, and flaps and
  `throttle_target` to 4000h (centre).
- **East and north.** Aileron moves east and elevator moves north, through `sub_1CFF`. Its speed is
  exponential: n = |control >> 3| >> 8, and the result is 2ⁿ − 1, or the mirror for negative values,
  built bit by bit with RCL/CMC. The speed is added to the 24-bit integer part (30D2..30D4,
  30DA..30DC).
- **Altitude.** altitude −= (throttle_target − 4000h) >> 2, clamped to 0..002EFFFFh.
- **View pitch.** The flaps tilt view_pitch by (flaps_hi − 40h) × 4, negated when the view is upside
  down. Past ±90° the view flips: pitch = 8000h − pitch, and bank and heading +8000h.
- **View bank and heading.** view_bank += [058F], view_heading −= [0591].
- **Editor values.** The position goes back to the editor values 2050/2052 (+4000h), through
  `sub_1CEC`.

### Wind (compute_wind 2F56, apply_wind 2F10)

- **Layers.** `compute_wind` (every 4th frame, phase 0) picks a layer by comparing the altitude word
  [30D6] (signed) with three tops:

  | altitude word | layer |
  |---|---|
  | ≤ [2073] | surface (2085/2087) |
  | ≤ [2075] | 1 (2081/2083) |
  | ≤ [2077] | 2 (207D/207F) |
  | above | 3 (2079/207B) |

  - **Units.** At run time the tops are the editor's "shear zone altitude" feet × 4E0Ch >> 16
    (× 0.305): 2997/5999/8997 ft become 913/1828/2742. They are compared against the altitude word,
    which is feet × 0.305 − [0906] (ground elevation, B4h at Meigs). So the layer changes about
    590 ft higher MSL than the editor value suggests. A memory dump taken while the editor is open
    shows the unconverted feet, because the editor converts back.
  - **Layer record.** Each layer is a word (low byte = speed, high byte = turbulence) and a direction
    word.
- **Drift.** The direction is the layer direction + [0915]. In the surface layer, every other call
  (a counter [1E2B] incremented and shifted) also adds [0917], as a gust. Both are 0 at Meigs.
  - wind_dx [1E27] = ((sin(dir) high byte × speed) × dt) << 1 >> 16, signed bytes
  - wind_dy [1E29] = the same with cos
  - [1E26] = turbulence
- **apply_wind** (every frame, only when airborne):
  - pos_east −= wind_dx and pos_north −= wind_dy (32-bit)
  - bank += (pos_north low byte + frame_counter low byte) × turbulence (signed bytes): a
    pseudo-random jolt
  - with turbulence > 5, also pitch += that jolt / 4, every 64th frame

### Engine (engine_update 2D00), every other frame

**State (DS):**

| address | meaning |
|---|---|
| 1DC0 | RPM, moved 1 step toward 1DC1 per call by `sub_2EEC`. It sets the IRQ0 rate, i.e. the engine note. |
| 1DC1 | RPM target |
| 1DC2 | power |
| 1DC4 | oil temperature rate |
| 1DC6 | oil pressure rate (0190h) |
| 1DC8 | faults: bit 0 oil leak, 1 oil pressure loss, bit 0 or 1 also limits power to 0FFFh, bit 2 left tank leak, bit 3 right tank leak |
| 1DC9 | fuel flow (FFh = −1) |
| 1DCA | carb ice counter |
| 1DCB | RPM deficit |
| 1DCC/1DCE | left tank, 24-bit (byte 1DCE is the gauge, 22h–23h full) |
| 1DCF/1DD1 | right tank |
| 1DD2/1DD3 | magneto switches L/R |
| 1DD4/1DD5 | magneto OK flags |
| 1DD6 | sound word (A140h running, 0 stopped) |
| 1DD8 | running |
| 1DD9 | oil temperature (word; the gauge is the high byte) |
| 1DDB | oil pressure (word) |
| 1DDD | 32-byte RPM table, by power >> 10 (10h..3Ah) |
| 1DFD | 32-byte windmill RPM table, by IAS >> 4 (00h..74h) |

**Keys.** The magneto keys are '1' off (magnetos 0), '2' left, '3' right, '4' both, '5' start (4).
'0' sets magnetos = 5 with both switches off, which is "off" for the engine check below. Note that
the key table at 05B1 starts at scancode 02.

**Engine running.**
- Outside reality mode ([204C] = 0) and outside war, the engine always runs. It is restarted
  automatically.
- In reality mode it stops when any of these holds:
  - magnetos = 5
  - no magneto is both switched on and OK
  - both tanks are empty (also in war)
- A stopped engine starts in any of these cases:
  - outside reality mode
  - by windmilling when IAS [0902] > 75 kt
  - with the starter (magnetos 4): a busy-wait of about 1.2 s, then magnetos are set to 3 (both)
    and the panel text is redrawn. In season 1 ([206A], winter?) the start fails unless
    frame_counter bit 2 is set, i.e. on half of the attempts.

**Power and thrust.**
- Power = throttle, or 0 when stopped.
- With carb heat on: −0800h, or −2000h while the ice counter [1DCA] counts down. That load also
  overwrites CL, so the windmill-RPM floor becomes 0 (original quirk, kept).
- Faults in bits 0/1 cap power at 0FFFh.
- A single magneto costs −0400h.
- thrust [08A4] = hi(power × [08E0]), with [08E0] = 0468h.

**RPM target.** table_1DDD[power_high >> 2], or 5 when stopped, but at least the windmill RPM
for the airspeed. The shortfall goes to [1DCB].

**Oil temperature.** Moves by the rate toward (64h stopped / AFh running / EFh oil leak) << 6 −
1900h. The rate is 7 running and 19h with a leak.

**Oil pressure.** Moves by [1DC6] toward 32h × 59h when running without bit 1, else toward 0.

**Fuel.** Each tank += flow × throttle_high (signed bytes; ×4 in war), 24-bit, clamped at 0. A leak
bit takes 1 more unit per call off the gauge byte.

**Carb icing.** Ice is set only by `sub_04FB`: [1DCA] = 14h when season = 2, throttle < 4000h and
(frame_counter & 3FFCh) = 0, i.e. once every 16384 frames. Ice has no effect with carb heat off. With
carb heat on, power drops by 2000h instead of 0800h until the counter runs out. In this version, carb
heat only ever costs power.

### crash_handler (0625)

- **Message.** crash_code is a byte offset into the pointer table at 0481:

  | code | message |
  |---|---|
  | 02 | MOUNTAIN CRASH |
  | 04 | CRASH (hard or banked landing) |
  | 06 | BUILDING CRASH |
  | 08 | SPLASH! |
  | 0A | CRASH! - LOWER YOUR GEAR NEXT TIME! |

- **Sequence.** After the message: a delay of 65535 × 3 MUL, `usermode_recall`, `editor_apply_state`,
  crash_code = 0, gear down, and `sub_0D01` (gear drag [083E] and the panel text).
- **Natives.** With no crash, the native returns at once. A crash is handed to the original (see
  above).

## 3.14 coverage sessions

Not part of `tools/trace_campaign.py`. Save the script below as a file anywhere and run it with the
repository root as the working directory. It prints `(name, frames, keys)`, and each line can be run
as `build/fs1 --frames N --keys "…"`.

To verify, add `--verify NAME` for each of the seven natives. All 12 sessions gave 0 mismatches.

```python
import os, sys
sys.path.insert(0, "tools")
from trace_campaign import keys_every

P2 = 22  # first row of editor page 2


def edits(start, pairs):
    """One editor visit: Esc, Enter down the rows typing each value, Esc."""
    values = dict(pairs)
    k, f = [f"{start}:Escape*2"], start + 40
    row = 0
    while row <= max(values):
        if row in values:
            for ch in str(values[row]):
                k.append(f"{f}:{ch}*2")
                f += 40
            k.append(f"{f}:Return*2")
            f += 40
            row += 1
            continue
        n = 1  # n plain Enters as one held key (auto-repeat)
        while row + n <= max(values) and row + n not in values:
            n += 1
        hold = 2 if n == 1 else 30 + 6 * (n - 2) + 2
        k.append(f"{f}:Return*{hold}")
        f += hold + 40
        row += n
    k.append(f"{f + 30}:Escape*2")
    return k, f + 120


def takeoff(f):
    return [f"{f}:F2*2", f"{f + 1500}:Keypad 2*2", f"{f + 1540}:Keypad 2*2", f"{f + 1580}:Keypad 2*2"], f + 2400


def session(name, edit_pairs, after, length, start_takeoff=False):
    k = ["120:A", "180:B"]
    f = 300
    if edit_pairs:
        ks, f = edits(f, edit_pairs)
        k += ks
    if start_takeoff:
        ks, f = takeoff(f)
        k += ks
    ks, f = after(f)
    return name, f + length, ",".join(k + ks)


S = [
    # take-off and climb
    session("takeoff_climb", None, lambda f: ([f"{f}:F2*2", f"{f + 1500}:Keypad 2*2", f"{f + 1540}:Keypad 2*2",
                                               f"{f + 1580}:Keypad 2*2", f"{f + 3000}:Keypad 8*2", f"{f + 3600}:F6*2"], f + 2400), 3000),
    # turns (ailerons, rudder, centring)
    session("turns", None, lambda f: keys_every(f + 600, 300, ["Keypad 4", "Keypad 4", "Keypad 6", "Keypad 6", "Keypad 6",
            "Keypad 6", "Keypad 4", "Keypad 4", "Keypad 0", "Keypad 5", "Keypad Enter", "Keypad 5"]), 1500, True),
    # wheels-up landing: 650 ft, 70 kt, idle, gear up, nose down -> 0A then 04
    session("gear_up", [(12, 650), (16, 70), (17, 0)],
            lambda f: ([f"{f + 20}:G*2", f"{f + 80}:F10*2", f"{f + 120}:Keypad 8*2"], f), 2500),
    # hard landing: 900 ft, 560 kt, nose down -> 04
    session("hard_landing", [(12, 900), (16, 560)], lambda f: keys_every(f + 20, 15, ["Keypad 8"] * 6), 2500),
    # water: 2 units east of Meigs over Lake Michigan -> SPLASH
    session("splash", [(11, 16673), (12, 640), (16, 80)], lambda f: keys_every(f + 20, 15, ["Keypad 8"] * 3), 2500),
    # banked landing -> 04 through the bank check
    session("banked_landing", [(12, 650), (16, 70), (17, 0)],
            lambda f: ([f"{f + 20}:Keypad 6*2", f"{f + 60}:Keypad 6*2", f"{f + 80}:F10*2"], f), 2500),
    # magnetos (reality mode, season 1): on the ground off/start/both, then in flight L, R, both,
    # off (windmilling), slow down, start, both, '0'
    session("magnetos", [(4, 1), (P2 + 2, 1)],
            lambda f: (lambda a, b: (a + b[0], b[1]))([f"{f + 100}:1*2", f"{f + 400}:5*2", f"{f + 1000}:4*2"] + takeoff(f + 1300)[0],
                      keys_every(f + 4000, 400, ["2", "3", "4", "1", "Keypad 2", "Keypad 2", "Keypad 2", "5", "4", "0",
                                                 "F10", "Keypad 2", "5", "4"])), 1500),
    # carb heat (reality mode, season 2)
    session("carb_heat", [(4, 1), (P2 + 2, 2)],
            lambda f: keys_every(f + 300, 400, ["H", "F8", "F8", "H", "F2", "H"]), 1500, True),
    # slew mode from 30000 ft with every slew key, then a long pitch roll-over and climb to the ceiling
    session("slew", [(3, 1), (12, 30000)],
            lambda f: (lambda a: (a[0] + [f"{a[1]}:Keypad 9*400", f"{a[1] + 500}:F2*2", f"{a[1] + 520}:Keypad 7*600"], a[1]))(
                keys_every(f + 60, 120, ["Keypad 8", "Keypad 2", "Keypad 4", "Keypad 6", "Keypad 7", "Keypad 1", "Keypad 9",
                                         "Keypad 3", "Keypad 0", "Keypad Enter", "Keypad +", "Keypad -", "Keypad 5",
                                         "Left Alt", "F1", "F2", "F3", "F4", "F5", "F6", "F7", "F8", "F9", "F10",
                                         "Keypad 8", "Keypad 2"], hold=90)), 6000),
    # winds in all layers with turbulence 6/7 (knots field high byte), 31000 ft (layer 3)
    session("high_alt", [(P2 + 7, 1800), (P2 + 8, 270), (P2 + 10, 320), (P2 + 11, 90), (P2 + 13, 215), (P2 + 14, 180),
                         (P2 + 16, 1546), (P2 + 17, 45), (12, 31000), (16, 110)],
            lambda f: ([f"{f}:F2*2"], f), 3000),
    # wind layers 1 and 2
    session("layers", [(12, 4500), (16, 110)],
            lambda f: (lambda a: ([f"{f}:F2*2"] + a[0], a[1]))(edits(f + 1500, [(12, 7500), (16, 110)])), 1500),
    # reality mode, reliability 0, long flight
    session("failures", [(4, 1), (P2 + 18, 0)], lambda f: ([], f), 9000, True),
]
for name, frames, keys in S:
    print(name, frames, keys)
```

**Coverage.** With the campaign, these sessions execute every instruction of the seven routines and
their helpers, except the following:
- 2D8C: IAS ≥ 512 kt. The editor airspeed does not get there.
- 2DAF/2DB2: carb ice. It needs the once-per-16384-frames trigger.
- 2DC3, 2E35/2E37, 2EAD, 2EBB, 2EC7, 2ED5: engine and fuel faults, and an empty tank. No failure
  occurred in 9000 frames with reliability 0, and the war-damage bits were not set.
- 3581, 359B: war-ammo edge cases.

These lines are written in the same pattern as the verified ones (register and memory effects, plus
the per-instruction cycle table), but they are unverified.

## Notes and problems

- `src/native.c` was not changed. The cycle check and the step log used during the work were
  temporary.
- `flight_motion_cycles.h` is generated data, 621 entries. If the CPU cycle model changes, it has to
  be regenerated. The scratch harness is about 40 lines: it includes `cpu8086.c`, loads
  `boot_mem.bin` and steps each address.
- Building from Git Bash fails because of the MSYS2 DLL path issue noted in 3.10. Building from
  PowerShell with `C:\msys64\mingw64\bin` first in `PATH` works.
