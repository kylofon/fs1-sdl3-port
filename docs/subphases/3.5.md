# 3.5 Horizon and sky/ground

Area file: `src/natives/horizon.c`. Extra coverage script: `tools/horizon_sessions.py`.

## Natives

All four are enabled by default.

| name | address | calls (campaign, all natives on) | mismatches | `.cycles` (fixed part) | flag_mask |
|---|---|---|---|---|---|
| `draw_sky_ground` | 0050:2AEA | 2271 | 0 | 30000 | none |
| `horizon_fill` | 0050:2B0D | 0 (2881 with `draw_sky_ground` off) | 0 | 30000 | none |
| `fill_sloped_horizon` | 0050:2C9E | 0 (2810 with `draw_sky_ground` and `horizon_fill` off) | 0 | 3000 | none |
| `radar_clear` | 0050:2AB0 | 0 (388 with `draw_sky_ground` off) | 0 | 42724 | none |

`python tools/verify_campaign.py` prints OK with every native on. The three inner natives get no
calls then, because `draw_sky_ground` runs them in C. They were verified separately:

    python tools/verify_campaign.py horizon_fill,radar_clear -- --native-off draw_sky_ground
    python tools/verify_campaign.py fill_sloped_horizon,fill_rows -- --native-off draw_sky_ground --native-off horizon_fill

Both print OK.

- `radar_clear` is never CALLed. `draw_sky_ground` reaches it with a JNE in radar view. It is still
  bound, so the trap fires when `draw_sky_ground` runs as original code.
- `.cycles` is only the fixed part. Each native adds the original's exact cost for the path it
  ran (the `cpu8086.c` model).
- Flags: no caller tests them. `main_loop` calls `draw_view_frame` next, and the internal calls
  are followed by POP, CMP or RET. The flags are not reproduced.
- Registers, segment registers and the words the CALLs and PUSHes leave below SP all match the
  original.

## Calls into other natives

The calls go through `native_call`, with the return address pushed first:
- `scenery_interp` (3.8, 0050:3CC0) for the capture step
- `fill_rows` (3.3); for the off-screen case's `jmp fill_rows`, the caller's return address is reused
- `draw_horizon_list` (3.4)

If `native_call` returns false (that native is off):
- The interpreter runs as original code: CALL emulated, single-stepped from 3CC0 with natives off,
  stepped cycles charged.
- `fill_rows` and the horizon list run from local C copies. The list uses the `raster.h` rasteriser.
- draw_line's cost is computed per path (`draw_line_cycles`: normal path, horizontal, vertical,
  x-major and y-major in both directions), so this fallback is cycle-exact.

## Cycle check

A temporary check in `verify_call` (not committed) compared the native's charged cycles with the
original's on every verified call:
- With `--native-off scenery_interp`, every call matched, in the campaign and in all attitude
  sessions. The dusk sessions also need `--native-off draw_horizon_list`, because 3.4 charges a
  fixed 7109 cycles for the list.
- **With the 3.8 native on, every `draw_sky_ground` call costs 30 cycles less than the original**
  (55185 vs 55215 level). The difference is in `scenery_interp`'s own accounting for the
  capture-mode horizon program (opcodes 40/41). It disappears with `--native-off scenery_interp`.
  This is for 3.8 to fix. `verify scenery_interp` reports original-cycles 0..0 there, so its own
  check does not catch it.

## Behaviour (formats)

- **Octant.** Octant = ((heading byte [30FC] + 10h) >> 4) & 0Eh selects the program at
  `[1D4F + octant]`.
- **Capture.** Capture is run with `eye_pos` zeroed and restored (xchg/push/pop). Captured
  records: x0,y0,x1,y1 at `horizon_list` 041F, FF ends.
- **Off screen** (`[041F]` = FF). Rows 0..69h are filled with `[1D4A]` (ground), or `[1D48]` (sky)
  when `[30F8]` < 0. The jump into `fill_rows` is a JMP, so its RET returns to `draw_sky_ground`.
- **On screen.** x is halved to bytes. AL = `[1D4C]`.
  - **Both ends' x/2 > [1D4C]** (2B98 path):
    - patterns: sky/ground by the sign of `[30FA]`, stored in 1D42/1D44
    - rows above the top end: `[1D42]`
    - sloped rows: `[1D42]` left of the boundary, `[1D44]` right of it
    - rows below the bottom end (to 69h): `[1D42]` again
  - **Otherwise** (2BF8 path): the patterns come from the sign of `[30FA]` + 40h and go into
    1D40..1D46. Above uses `[1D40]`, below uses `[1D46]`. If the ends are swapped, 1D42 and 1D44
    are exchanged.
- **fill_sloped_horizon** (BL..CL rows, BH/AH = boundary x in bytes at the top and bottom):
  - step = IDIV((AH−BH) << 8, rows), 8.8 fixed point, stored in `[1D4D]`
  - each row: first add the step, then x bytes of BP and 80−x bytes of `[1D44]` (words plus a
    byte for odd counts)
  - on return: AX = `[1D44]`, BP unchanged, CX = 0, SI = FFFF, BX = 2·(row after the last),
    DX = last boundary, DI past the last row
- **Dusk.** `[0412]` & 2 and a captured line: `[30C8]` = 8008h, then `draw_horizon_list`.
- **radar_clear.** Sets 3802/3804/3800 = 0848h and calls `clear_view_buffer`. Then it writes
  five fixed words into the back buffer: 07F7=4001, 27F7=7F7F, 0847=4001, 2847=4001,
  0897=7007. These are the radar view's centre marks.

## Attitude coverage (`tools/horizon_sessions.py`)

The campaign flies mostly level. These sessions use the editor (slew = 1, altitude 3000; with
user mode 3 for dusk) and then slew attitude keys:
- KP7/KP9: bank rate ±80h
- KP1/KP3: heading rate
- F1..F9: pitch rate, (flaps − 40h)·4 per update

| session | what it covers |
|---|---|
| level | the level reference |
| roll, roll_rev | continuous rolls both ways through knife edge and inverted |
| pitch_up, pitch_down, pitch_up_slow | pitch to ±90°: sky only, ground only, steep horizon |
| roll_pitch, roll_rev_pitch_down, tumble | combined roll, pitch and turn: inverted with pitch, steep banked lines, the 2B98 path |
| dusk_roll, dusk_pitch, dusk_mix | the same at dusk, with the horizon line |
| flight_dive, dusk_flight_dive | free flight (no slew) from 8000: dive, pull, crash |
| editor_pitch20, editor_bank45 | values typed into the editor's Pitch/Bank fields |

    python tools/horizon_sessions.py verify draw_sky_ground [shots TAG]

All 16 sessions: 0 mismatches (120..441 calls each). Measured original costs range from 49005
(off screen) to 86411 (dusk, steep).

Notes:
- A real loop could not be scripted reliably. In flight, pitch past 90° is folded into
  bank/heading + 180° (`fix_loop_over`), so a loop's view angles are the inverted and pitched
  states that the roll and tumble sessions already cover.
- Slew pitch stops at ±90°.
- Editor rows count Returns, and North and East take two each: Altitude 12, Pitch 13, Bank 14,
  Heading 15, Airspeed 16. The campaign's `editor_set(…, 10, 3000)` therefore does not edit
  Altitude.
- Typing a Pitch or Bank of 3 or more digits leaves the editor unable to exit with Esc. The
  original does this too.

## Symbols (symbols.txt syntax)

```
code 0050:2AB0 radar_clear           ; [code] clear both banks (0848h words) + radar centre marks; reached by JNE from draw_sky_ground
code 0050:2C9E fill_sloped_horizon   ; [code] rows BL..CL, boundary BH->AH bytes (8.8 DDA step [1D4D]); left BP, right [1D44]
var 0618:1D40 band_patterns table    ; [code] 4 words: above / sloped-left / sloped-right / below patterns of horizon_fill
var 0618:1D4C horizon_x_limit byte   ; [code] x/2 threshold choosing the horizon_fill fill path
var 0618:1D4D horizon_slope word     ; [code] 8.8 boundary step per row (fill_sloped_horizon)
```
