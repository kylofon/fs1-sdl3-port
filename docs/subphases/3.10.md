# 3.10 Indicators and needles

Area file: `src/natives/indicator.c`. Shared helpers: `src/natives/panel.h`.

## Natives

All six are enabled by default. Every one is cycle-exact: each native adds the emulated
cycles the original takes on the path it ran (the `cpu8086.c` model), so the timeline is
unchanged. With the natives on and off, all screenshots matched byte for byte (see Verification).

| name | address | calls (campaign) | mismatches | `.cycles` (typical) | measured range | flag_mask |
|---|---|---|---|---|---|---|
| `draw_indicator` | 0050:2111 | 5449 | 0 | 118 (unchanged frame) | 118..1499 | IF |
| `draw_needle` | 0050:1D20 | 6388 | 0 | 181 (unchanged angle) | 181..16733 | IF |
| `draw_needle2` | 0050:1DE8 | 2246 | 0 | 183 (unchanged angle) | 183..9752 | IF |
| `blit_sprite` | 0050:4DE0 | 44 | 0 | 295 | 295..2284 | IF |
| `blit_or` | 0050:4DF6 | 0 (370 with callers off) | 0 | 154 | 154..2215 | IF |
| `indicator_erase` | 0050:218E | 0 (466 with callers off) | 0 | 132 | 132..3330 | none |

`blit_or` and `indicator_erase` get no calls when every native is on, because all of their
callers (`draw_indicator`, `blit_sprite`, `draw_needle2` through 20E0) are natives that call the
C versions directly. They were verified on their own with
`python tools/verify_campaign.py blit_or,blit_sprite,indicator_erase -- --native-off draw_indicator --native-off draw_needle --native-off draw_needle2`,
which gives 370 / 140 / 466 calls and 0 mismatches.

No caller tests flags after these routines; every call is followed by RET, MOV or CALL. The
mask holds only IF: `draw_indicator` runs CLI, and `blit_or` ends with STI. The natives set IF
the same way.

Two routines go beyond the brief:
- `draw_needle2` (1DE8) is the second needle drawer, used by the VSI, the tachometer and the
  altimeter's small hand. `draw_needle` calls it for the altimeter, so it needed a C version anyway.
- `blit_sprite` (4DE0) is a 3-instruction prologue that falls into `blit_or`.

3.11 should not bind 1DE8 or 4DE0 again.

### Stack and registers

The natives reproduce everything the originals leave behind, including the words that their
CALLs and PUSHes write below SP. These are written through a virtual SP, so `--verify` compares
them as well. Without this, the stack words would show up as memory mismatches. Notable
register side effects:
- `draw_indicator` leaves DS = [0000:0120].
- The needle routines leave DS = [0000:0120], ES = B800, and BP clobbered.
- On an unchanged angle, `draw_needle` returns AX = the return address of its 1DDA check, from
  the `pop ax`.

### Divide-overflow fallback

`sub_20E0` divides [0900] by 5F5 after CWD. A negative [0900] would overflow and raise INT 0. The
campaign never reaches this. Natives that could reach it (when [0914] != 0 and [0900] < 0) run the
original routine instead: they single-step with natives off and charge the measured cycles. This
path was tested by forcing it: 930 + 284 calls, 0 mismatches.

## Formats learned

**Indicator descriptor** (BP), for `draw_indicator`:

| offset | meaning |
|---|---|
| +0 | screen offset of the indicator's origin (B800) |
| +2 | pointer to the sprite-pointer table |
| +4 | pointer to the frame table, one word per frame |
| +6 | new frame |
| +7 | drawn frame |
| +8 | saved rectangle: screen offset |
| +A | saved rectangle: size word (DL words × DH lines; 0 = nothing to erase) |

Each word in the frame table has three fields:
- low nibble: x offset in bytes, added to +0
- bits 4–7: index into the sprite-pointer table
- high byte: number of lines to move up from the origin, applied with the CGA interleave

A sprite is a size word followed by the sprite words. If +6 == +7, the routine returns unless
`[1400]` (a forced-redraw counter, never nonzero in traces) is set; in that case it decrements
the counter and redraws.

To draw, the routine first restores the saved rectangle from the clean panel copy. Then it
stores the new rectangle in +8/+A and ORs the sprite in with `blit_or`.

**Clean panel copy.** The word at 0000:0122 holds the segment of a copy of the panel. The
startup code copies B800:0FA0.. there (around 0050:5DFC). `indicator_erase` and the needle erase
(1F63) restore from that copy. The sprite source of `blit_or` is the caller's DS:SI.
`draw_indicator` and the needle routines use [0000:0120], the data segment 0618. Only
erasing uses [0000:0122].

**blit_or geometry.** DI is the bottom line of the sprite. The sprite is drawn upward: +1FB0
from an even line goes to the odd line above, and +E000 from an odd line goes to the even line
above. The starting bank comes from a signed `DI > 1F40` check. DL = 1 uses a separate one-word
loop.

**Needle descriptor** (CX):

| offset | meaning |
|---|---|
| +0 | hub screen offset for the upper half |
| +2 | hub screen offset for the lower half |
| +4 | drawn code (FF = none) |
| +5 | screen offset of the drawn sprite |
| +7 | size word of the drawn sprite |
| +9 | angle, for descriptors used as a second needle |

The angle AL (0..FF) is folded into a quadrant. The direction comes from `needle_quadrant_tbl`
DS:09BD (65 entries, index 0..40), and the code is that direction plus quadrant bits:
- 40 = lower half: drawn downward with steps 2000/E050, hub at +2
- 80 = left half: mirrored, hub at +0 or +2

| angle | quadrant | code bits |
|---|---|---|
| 00–40 | upper right | 00 |
| 41–80 | lower right | 40 |
| 81–C0 | lower left | C0 |
| C1–FF | upper left | 80 |

The row steps go in [0910]/[0912].

Sprites come from two tables, indexed by (code & 3F)·2:
- `draw_needle`: the pointer table at DS:0961
- `draw_needle2`: the pointer table at DS:098F

Mirrored sprites are drawn right to left from hub−1. Each byte goes through the CGA 2-bpp
bit-reversal table at DS:12B4, and the two bytes of each word are swapped.

**Needle erasing.** If the code changed, the old needle (+4/+5/+7) is restored from the clean
copy before the new one is ORed in. `draw_needle` with AH != 0 then redraws the second needle
[090D], which is the altimeter's small hand at descriptor 0943, through `draw_needle2` with AH = 1
(forced). With [0914] != 0 (only set by `upd_altimeter`), `draw_needle2` also erases indicator
rectangle 13AC and blits one of 5 sprites (the record table at DS:13B8) chosen by
[0900] / 5F5. That is the altimeter's altitude-band marker, one step per ~5000 ft.

Needle descriptors:

| descriptor | instrument |
|---|---|
| 092F | airspeed |
| 0939 | altimeter, large hand |
| 0943 | altimeter, small hand |
| 094D | VSI (`draw_needle2`) |
| 0957 | tachometer (`draw_needle2`) |

| 1419 | [1DDA] |

## New symbols (docs/symbols.txt syntax)

```
code 0050:1DE8 draw_needle2          ; [code] AL = angle, AH bit0 = force redraw, CX = descriptor; sprites DS:098F
code 0050:1DDA needle_check_same     ; [code] cmp code,[bx+4]: equal -> pops and returns from draw_needle
code 0050:1EE3 needle_redraw_second  ; [code] if [090F]: draw_needle2 of [090D] at its +9 angle
code 0050:1F63 needle_erase          ; [code] restores the needle drawn at BX from the clean panel copy
code 0050:20E0 alt_band_marker       ; [code] if [0914]: erase 13AC, blit_sprite record [13B8 + 2*([0900]/5F5)]
code 0050:4DE0 blit_sprite           ; [code] ES=B800; blit_or with record DS:BX (+0 offset, +2 size, +4 words)
var 0618:0900 alt_display word       ; [code] altitude word + [0906], used for the band marker
var 0618:0904 needle2_force byte     ; [code] AH of draw_needle2
var 0618:090D second_needle_desc word ; [code] descriptor redrawn after draw_needle (0943)
var 0618:090F needle_redraw2 byte    ; [code] AH of draw_needle
var 0618:0910 needle_row_step word   ; [code] row step from an even line (1FB0 up / 2000 down)
var 0618:0912 needle_row_step2 word  ; [code] row step from an odd line (E000 up / E050 down)
var 0618:0914 alt_band_on byte       ; [code] set by upd_altimeter around draw_needle
var 0618:0961 needle_sprites table   ; [code] sprite pointers for draw_needle, by direction 0..3F
var 0618:098F needle2_sprites table  ; [code] sprite pointers for draw_needle2
var 0618:12B4 cga_mirror_tbl table   ; [code] bit-reversal of 2-bpp pixels (mirrored needles)
var 0618:13B8 alt_band_sprites table ; [code] 5 blit_sprite records
var 0618:1400 indicator_force byte   ; [code] forced-redraw counter for draw_indicator
var 0000:0122 panel_copy_seg word    ; [code] segment of the clean panel copy (erase source)
```

## Helpers for 3.11 (`src/natives/panel.h`)

Each `panel_call_X(pc, ret_ip)` emulates `CALL X` from the current CPU state: it writes `ret_ip`
at SS:SP−2 and runs the C routine with all of its stack writes. Registers, segment registers,
flags (IF) and memory end up as the original leaves them. SP and IP are not changed.
`panel_cycles()` returns the original's cycles for the routine. That count includes its RET
and excludes the CALL, so a 3.11 native should charge 21 for the CALL plus this value.

Available calls:
- `panel_call_blit_or`
- `panel_call_blit_sprite`
- `panel_call_indicator_erase`
- `panel_call_draw_indicator`
- `panel_call_draw_needle`
- `panel_call_draw_needle2`

Example: a native `gauge_upd_1401` would set BP and [1407], then call
`panel_call_draw_indicator(pc, 0x02E1)`.
