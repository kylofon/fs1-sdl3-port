# 3.9 Text and font

Area file: `src/natives/text.c`. Shared helper: `src/natives/textdraw.h`.

## Natives

All are enabled by default. Each one charges exactly the cycles the original uses in the emulator's
cycle model. The entry's `.cycles` is the fixed part, and the native adds the per-glyph part itself
(checked call by call over the whole campaign). So screenshots with the natives on and off are
byte-identical.

| Name | Address | Campaign calls | Mismatches | Cycles (original) |
|---|---|---|---|---|
| `print_str` | 0050:1225 | 712 | 0 | 110 + 275/glyph |
| `print_str_dim` | 0050:122B | 2941 | 0 | 93 + 275/glyph |
| `print_str_mask` | 0050:122E | 2407 | 0 | 89 + 275/glyph |
| `print_str2` | 0050:1282 | 82 | 0 | 99 + (375 + 20·DL)/glyph |
| `print_str_list` | 0050:15E1 | 30 | 0 | 55 + 171/string + 275/glyph |
| `clear_screen` | 0050:15EC | 30 | 0 | 42457 |

`python tools/verify_campaign.py` prints OK: 0 mismatches over all 14 sessions, with every native enabled.

Flags: no caller tests flags after any of these routines. Every call site is followed by a `mov`,
`ret`, `stc`, `pop` or a jump to such code. So `.flag_mask` is 0 for all of them. The natives still
set the flags as the original's last instruction does: `SUB AL,20h` for the print routines,
`CMP word,0` for the list and `XOR AX,AX` for the clear.

Registers are left exactly as the original leaves them:
- AX: AL = terminator − 20h. AH is the high byte of the last glyph word written, or of the screen
  offset if the string is empty.
- BX = (last char − 20h)·10.
- SI points past the terminator, and DI after the last cell.
- print_str2 also sets CL = DL once a glyph is drawn.
- print_str_list writes the return address 15E9 below SP, as its `CALL print_str` does.
- clear_screen leaves AX = CX = 0 and DI = 3090.

The natives honour DF in LODS and STOS, although the game always has it clear.

## Font location (finding)

The font is **not self-patched**. The disp16 of `mov ax,[bx+0000]` at 0050:1245 (and the `+2..+8`
loads at 1250/125B/1266/1271, plus the matching loads in print_str2 at 129F… and 1310…) is written
only by the boot loader (0050:004A, the load stream). The value is 0000. A write watch on
0050:1245–1275 through the menus and a flight sees no other writer, and the trace map has no SMC there.

So the font is simply the **first 960 bytes of the data segment**, DS:0000–03BF: 96 glyphs for 20h–7Fh,
each 10 bytes. It moves because the data segment moves:
- The loader copies the data block to **0686:0000** (linear 06860), and the startup menus run with
  DS = 0686.
- `startup` (5C9F) then calls `sub_5CCD`. This sets ES = CS + (5C70h >> 4) + 1 = 0618, CX = 3A84h,
  SI = DI = BP = 0. It then jumps to 0050:01F0 → `store_ds_for_isr` (0732). That routine
  `rep movsb`s the 3A84h-byte data segment down to **0618:0000** (linear 06180, over the startup code
  at 0050:5C80+, hence the SMC marks there), stores 0618 to 0000:0120 and sets DS = 0618.

The natives read the five displacements from the instruction bytes of the loop they replace, and
use the caller's DS, exactly as the original. They stay correct if either changes.

Glyph format: each row is one word in screen byte order. The low byte holds the left 8 pixels,
MSB first, in the 640×200 mode the game uses (composite artifact colour). For example, 'A' row 0
is 3Fh C0h.

## Routine details

- **print_str_mask** (122E): ES = B800 (the immediate at 122F), then `LODSW` → DI. For each byte
  in 20h..7Fh (`SUB AL,20h / JGE` is a signed test, so bytes 80h–FFh also terminate), it writes
  5 words ANDed with CX via `STOSW`. After rows 0–3, DI steps by +1FFE and +E04E alternately (even
  bank → odd bank and back). After row 4 it steps by FF60, to the next cell 2 bytes right.
- **print_str** (1225) uses CX = FFFF, and **print_str_dim** (122B) uses CX = 8888. Both fall into
  print_str_mask.
- **print_str2** (1282): ES = B800, mask BP. Each row word is byte-swapped, shifted right by CL = DL,
  and swapped back, so it shifts right DL pixels across the two bytes. If DI ≥ 1F40 (signed `JL`),
  the first row is on an odd line and the steps are E04E, 1FFE, … . Otherwise they are 1FFE,
  E04E, … . Callers: `sub_14C9` (OBI course digits, from int8) and `sub_33C2` (war status line).
  **The even-line path (1293–1303) never runs in the campaign.** The native implements it from the
  listing, but it is unverified.
- **print_str_list** (15E1): `CMP word [SI],0 / JE ret / CALL print_str / JMP`.
- **clear_screen** (15EC): ES = [DS:03C2], zeros 848h words at ES:0000 and ES:2000.
- There is a fourth entry into the print loop at **0050:121A**. It sets CX = 8888 and
  ES = [view_buf_seg], then jumps to 1233. This is the tail of `fmt_signed_dec`, which prints its
  digits dimmed into the back buffer. It enters at an unhooked address, so it always runs as the
  original.

## Reusable renderer: `src/natives/textdraw.h`

Header-only (static inline), for other natives and phase 4:
- `TextDraw`: the loop state (DS:SI, ES:DI, mask, five font displacements, odd-first, optional
  shift, and the resulting AX/BX and glyph count).
- `textdraw_string(pc, &t, dir)`: draws one string body exactly as the original loop does, through
  `cpu_read*`/`cpu_write*` so verify sees it.
- `textdraw_read_disp(pc, insn_disp[5], disp[5])`: reads the font displacements from code.
- `textdraw_font_base(pc)`: the font offset in DS (the disp at 0050:1247).
- `textdraw_glyph(pc, ch, rows[5])`: the 5 row words of a glyph from DS 0618. This is valid once
  the startup menus are over.
- `textdraw_is_glyph(ch)`: whether a byte is drawn (20h–7Fh), and constants for the CGA steps.

## New symbols (symbols.txt syntax)

    data 0618:0000 font                  ; [data] 96 glyphs 20h-7Fh, 10 bytes each (5 row words, low byte = left 8 px); at 0686:0000 before relocation
    code 0050:121A fmt_signed_dec_print  ; [code] CX=8888, ES=[view_buf_seg], jumps into print_str_mask's loop (1233)
    code 0050:5CCD set_reloc_args        ; [code] ES=0618, CX=3A84 (data segment size), SI=DI=BP=0 for store_ds_for_isr

Suggested corrections:
- `print_str_mask`: "font is DS:0000 (disp16 0000 written only by the loader), not self-patched".
- `print_str2`: "DS:SI string, mask BP, right shift DL; DI>=1F40 starts on an odd line".
- `store_ds_for_isr`: "moves the data segment 0686→0618 (3A84h bytes) after the startup menus".

## Framework notes

No framework change is needed. The natives add their per-glyph cycles to `pc->cpu.cycles`
themselves, on top of the entry's fixed `.cycles`. Under `--verify` the original's cycles are kept
anyway. A per-call cycle callback in `NativeEntry` would make this explicit, if the coordinator
prefers that.
