# 3.17 War mode

Area file: `src/natives/war.c`, header `src/natives/war.h`. Coverage/verify script: `tools/war_sessions.py`.

## Natives

All are enabled by default. Each body is an instruction-by-instruction transliteration on the
emulated registers (stack words from CALL/PUSH included) and adds the original's cycles on the path
it ran (cpu8086.c model). With every other native off, a temporary check in `verify_call` (not
committed) found the charged cycles equal to the original's on every verified call.

| name | address | campaign calls (all on) | calls, callers off (campaign + war sessions) | mismatches |
|---|---|---|---|---|
| `war_frame` | 0050:3020 | 2,268 (+6,449 in war sessions) | – | 0 |
| `war_enemy_update` | 0050:30AB | 0 | 1,944 + 38,748 | 0 |
| `war_guns` | 0050:344F | 0 | 387 + 6,485 | 0 |
| `war_bomb_fall` | 0050:3521 | 0 | 387 + 6,485 | 0 |

"Callers off" = `--native-off war_frame --native-off flight_params`:

    python tools/verify_campaign.py war_enemy_update,war_guns,war_bomb_fall,war_ammo_dec,war_score_add,war_status,war_scope_clear,ground_service,war_ground_reset -- --native-off war_frame --native-off flight_params
    python tools/war_sessions.py -- --native-off war_frame --native-off flight_params
    python tools/war_sessions.py            # all on: war_frame 6,449 calls, 0 mismatches

`war_frame` calls the other war bodies directly in C, and 3.14's `flight_params` contains the
1B84 tail (and calls 1BB0/3595 itself), so with everything on these entries get 0 calls; they are
reached inside verified `war_frame` calls. `war_ammo_dec` as an entry is only reached from war_guns
and 1B84, i.e. only through C; its body runs inside war_guns and ground_service (both verified).
`war_score_add` and `war_ground_reset` are also called from the editor's apply code (3C19/3C1C).

No `flag_mask`: the callers follow these routines with CALL/MOV/RET.

Nested calls go through `run_from()`: an enabled native at a reached address runs via
`native_call()` (print_str/print_str2 from 3.9, plot_pixel(_es), draw_line_list, project_dot,
rotate_point, fmt_dec4); anything else is single-stepped as original code (with the hook map off so
no nested `--verify` starts). Because rotate_point and draw_line charge fixed `.cycles`, a verified
`war_frame` with those natives on charges a few hundred cycles more or less than the fully-original
run; that is the same cost the game sees with war_frame off and the other natives on.

`war.h` exports `war_call_ground_reset`, `war_call_score_add`, `war_call_ammo_dec` and
`war_ground_service_body` for 3.14/3.16 if they want them (3.14 currently emulates those parts).

## War mode, as the code does it

**Starting.** The editor field "Europe 1917" sets `war_mode` [204E]. The first war frame sets
[1E59] and masks [208B]. Enemies are not moved until war is *declared*: [1E5A] bit 0 is set by
**W** (`key_w`) or by a bomb hitting a target. `war_status` then prints "BEGIN WAR!!", sets
[1E5A] = 3 and pauses with a 3 x 65535 DEC/JNZ loop (3,538,912 cycles; in the native one long step,
the timer ticks are delivered afterwards by the IRQ0 backlog). W does nothing afterwards.

**Enemy record** (6 records of 29 bytes at 1F3B, 1F58, 1F75 = squadron A, 1F92, 1FAF, 1FCC = B):

| off | meaning |
|---|---|
| +0..2 | east, 24 bits (bytes 1..3 of pos_east) |
| +3..5 | altitude, 24 bits |
| +6..8 | north, 24 bits |
| +9 | on the panel scope (FF) or not (0) |
| +A | in gun range (set when visible, close and centred) |
| +B, +D | attack box: start when player east.hi < [+B] and north.hi >= [+D] |
| +F, +11 | give up when east.hi >= [+F] or north.hi < [+11] |
| +13, +14, +15 | speeds east, altitude, north (signed bytes, 1/256 hi-unit per frame) |
| +16 | firing distance |
| +17 | unused |
| +18 | loaded into AL when not firing (dead value) |
| +19 | state: 0 shot down, 1 home/parked, 2 attacking |
| +1A | evasion timer after firing |
| +1B | pointer to the home position (1E5D squadron A, 1E66 squadron B) |

Squadron A's home is the field at east -8982, north 1033; B's at -8970, 1002. The player's home
field is -8938, 1033.

**Movement.** Each frame the target is home (state 1) or the player (state 2); the 24-bit delta
target - enemy goes to 1E6F/1E72/1E75 (+ high bytes 1E71/1E74/1E77). Each axis then moves by its
speed in the direction of the delta's sign (a zero delta counts as positive, so enemies jitter
around the target). Enemies at home sit on their field.

**Attacking and firing.** In state 2 the distance is |dE| + |dA| + |dN| (one's complement for
negatives). If it is <= [+16] the enemy fires: "ENEMY FIRE!" ([1E78]), hits [1E5C] + 1, damage
(below) and [+1A] = FF. While [+1A] != 0 the enemy breaks off: it counts down, descending every
other frame (not below 0) while the counter is >= 80h, then climbing one unit a frame.

**Damage** (`35DB`, from the hit count; thresholds lower once 4 enemies are down):
hits > 7 (1) → fuel leak left ([1DC8] bit 4) in the first 64 frames of 256; > 14h (> 1) → also leak
right (bit 8); > 23h → bit 1 (engine: RPM cap, oil temperature); > 28h (> 7) → bit 2 (oil pressure);
> 3Ch (> 14h) → [1E83] = 1, left wing lift zero. Landing at the home field and stopping repairs all.

**Drawing an enemy.** If every eye-relative axis (low word of the position minus `eye_pos`) is under
10000, it is rotated (rotate_point), put on the panel scope (`334A`: column 87h + 4x/256, line
ABh - 8z/256, colour by height: below / level / above) and projected with project_dot in capture
mode. If captured: depth >= 2BCh → one dot (`plot_pixel`); otherwise a sprite (`5BAA`, five sizes
from the table at 3A10: 5BD1, 5BE4, 5BFA, 5C11, 5C39), drawn bottom-up into the back buffer. DI = 2
(depth <= C8h and within x 46..54, y 23..3B of the view) → in range: [+A] = 1, "IN RANGE".
Parked enemies (state 1 and altitude.hi 0) are never "in range".

**Guns** (Space → [1E7C] = 3 if ammo): three bullets on three frames, alternately from the left
(41,69) and right (5F,69) gun, ammo - 1 each. Bullet records (6 bytes at 1EE6..1F39): life, aim
point, current point, initial life 0F. Each frame a bullet moves a quarter of the way to the aim
point; once its life is below 10, it shoots down the first enemy (from record 6 back) whose [+A] is
set: score + 1, kills [1E50] + 1, state 0, and a 100-dot explosion. Bullets are drawn for 19h frames
after the last shot. The explosion dots come from bytes at DS:0830, which are live flight variables
(pseudo-random).

**Bombs** (X, `key_x_bomb`): bombs_left - 1, [0575] = [0919], whistle [0540] = 64h (the sound code
raises the tone while [0575] != 0). `war_bomb_fall` takes 32h a frame; [1E53] is cleared every
frame and set by the scenery while the aircraft is inside a target box below altitude.hi 7. If it is
set on the frame the bomb lands: score + [1E53] (20 or 10), war is declared and a 200-dot explosion
(colour 2002) is drawn. So the bomb hits where the aircraft is when it lands.

**Status line.** Left: IN RANGE / ENEMY FIRE! / blanks, printed when it changes ([1E82]). Right:
AMMO, SCORE or BOMBS by `frame_counter & 18h`, so it cycles every 8 frames by itself.

**Re-arm** (1B84, the tail of flight_params): the scenery sets [0406] = 1 on an airport ramp, 2 on
the war home field. With airspeed 0: `1BB0` refuels, repairs, clears hits and puts all enemies back
to state 1; on the war field also ammo = 100 and bombs = 5. [0406] is cleared every call.

## Coverage

`python tools/war_sessions.py --coverage FILE` runs the three sessions with every native off and
writes a trace map. Reached for the first time: attack/give-up of both squadrons, enemy fire, the
evasion dive and climb, damage, the panel scope dot (**plot_pixel at 3398**, now verified inside
war_frame), bomb drops, ground re-arm, and the burst/bullet paths.

Still not reached by script (138 instructions): an enemy captured *in the view* (31E5..3269, so the
plot_pixel at 31FB and the sprites 5BAA/5BD1..5C6D), shooting one down (34CD..34E3, 35AB), a bomb
hit (3534..3544), damage levels from 35FB on, and the score wrap. The scripted flight always has the
enemies behind or beside it; aiming needs a human. These paths are written to the same rules and
reviewed against the listing, but not verified.

## Problems / notes

- The editor field numbers changed on main; the sessions only use field 6 (Europe 1917) via the
  editor and then fly.
- Interrupts are held during a native; the BEGIN WAR!! pause (3.5M cycles) now relies on the IRQ0
  backlog to deliver the missed ticks afterwards.
