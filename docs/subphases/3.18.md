# 3.18 Keyboard and controls

Area file: `src/natives/keys.c`, headers `src/natives/keys.h` (`native_iret`) and
`src/natives/keys_cycles.h` (generated by `tools/gen_keys_cycles.py`). Key sessions and the
on/off screenshot check: `tools/key_sessions.py`.

The keyboard interrupt, `key_dispatch`, every handler in the `key_handlers` table (DS:05B1) and
`key_repeat_accel` are natives, plus the shared routines the handlers jump or fall into
(`set_flaps`, the control indicators, ...), because other code calls them too.

The emulated keyboard path is unchanged: SDL → `pc_key_event` → port 60h → IRQ1 → `int9_keyboard`.

## Natives

All are enabled by default.
- Each body is an instruction-by-instruction transliteration on the emulated registers, with the
  stack words of CALL and PUSH. It charges the original's cycles on the path it ran (cost table
  from the cpu8086.c model, as in 3.16).
- `FS1_KEYS_CYCLE_CHECK=1` compares every non-nested call with the original single-stepped first.
  It found no difference in any of the 20 sessions (campaign + key sessions), in three runs:
  - all natives on;
  - `int9_keyboard` and `key_dispatch` off, so the handlers are entered by the CPU;
  - all handlers off too, so the shared routines are entered by the CPU.
- A deliberate +7-cycle error was reported, so the check works.

Notes on the counts:
- `int9_keyboard` calls `key_dispatch` and the handlers through `native_call()`, so they are
  counted but checked as part of the interrupt's verified call.
- `key_dispatch` is also reached directly from `demo_step` (in the timer interrupt), and is then
  verified on its own.
- **Zero calls.**
  - `magnetos_store` (0A19) is called only from 2D5E. That code is reached inside other natives'
    verified calls, which run as original code. In play it runs natively (6 calls over the sessions).
  - `key_enter` does nothing unless `enter_unhooks` [0418] is set, which never happens in a trace.
    The campaign never presses Enter outside the editor. The key sessions do (1 call).
- `rudder_update` (0FE2) is only jumped to, never called, so it is not an entry.
- No `flag_mask`. None of the callers reads the flags after these routines; the interrupt's IRET
  restores them.

### Interrupt entries

Natives work for interrupt entries as they are; the framework needs no change.
- `cpu_interrupt` pushes FLAGS, CS, IP and jumps to the vector. The dispatch hook then fires at
  0050:0970 like at any other bound address.
- The entry has `.far = true`, so `--verify` finds the return IP and CS on the stack, as it does
  for RETF.
- The native ends with `native_iret` (in `keys.h`). It pops IP, CS and FLAGS and applies the
  fixed flag bits that cpu8086.c's IRET applies.

The native reproduces the handler's I/O:
- the port 60h read, which clears `kbd_full`;
- the port 61h acknowledge pulse (bit 7 set, then the old value back);
- the EOI to port 20h.

### Ctrl+Alt+Del

`key_dispatch` sees Delete (53h) with `last_scancodes` = 381Dh (Ctrl, then Alt). It then:
1. loads DS from `bda_seg` [0595] (0040h);
2. writes the warm-boot flag 0040:0072 = 1234h;
3. jumps to F000:E05B.

The natives leave CS:IP at F000:E05B and stop; pc.c traps that address to a reboot.

`--verify` cannot check that call, because the original never returns:
- `run_original` steps through the reboot until the step cap.
- `verify_campaign.py` now has a `NO_VERIFY` table: in the `reboot` session, `int9_keyboard` and
  `key_dispatch` stay enabled but are not verified.
- `key_dispatch` is listed too. It is reached directly when `int9_keyboard` hands a call back
  (see below).
- That session (and `keys_reboot`) is checked by screenshots instead.
- See "Framework notes".

### Interrupts (hand-back)

The scheme is the same as 3.14 and 3.16.
- **Timer.** The indicator handlers call `draw_indicator` → `blit_or`, which executes STI. So the
  timer interrupt can arrive inside the keyboard interrupt.
- **Keyboard.** `kbd_poll` runs after every instruction. It can latch the next scancode, raise
  IRR1 and set `kbd_next_cycle` in the middle of the handler.
- A native holds both until it returns. So a call that is not nested in another native runs with
  an undo log. If the timer or keyboard would have fired within its cycles, the native:
  1. undoes its memory writes;
  2. restores the CPU and the device state (PIC, PIT, keyboard, port 61h, speaker log; the same
     ranges as native.c's `--verify` snapshot);
  3. performs the original's first instruction, so the original continues with interrupts.

How often each ran natively in play (all 20 sessions):

| Native | Ran natively |
|---|---|
| `int9_keyboard` | 72% (1,425 calls) |
| `key_dispatch` (handed-back interrupts, demo) | 70% |
| `elevator_update`, `controls_redraw` | 85-89% |
| handlers entered by the CPU (only after a hand-back) | 0-100% |

## Key behaviour vs the README key table

What the code does, where it differs from or adds to `README.md`. All of it is the same with the
natives on and off.

- **Scroll Lock with the radar off** sets `selected_item` = 1 (README: only "radar off"). The next
  keypad key (KP8 9 6 3 2 1 4 7 5) then:
  - picks a view direction instead of its normal action (`key_repeat_accel`);
  - stores the view routine from `view_dir_fns` [05A1] in `view_dir_fn` [059B];
  - sets `view_not_forward`.

  Seen in a screenshot: KP2 shows the view behind. So "key_repeat_accel" is really the
  view-direction selector. The name is kept from symbols.txt.
- **D** sets the directional gyro to the compass (README: no visible effect).
  - The gyro drifts: the routine at 0563 adds FFh to the 24-bit value 03F8-03FA each time it runs.
  - `heading_readout` shows view_heading + `dg_offset` [03F9] - wind offsets.
  - D sets `dg_offset` so the readout equals `hdg_display`.
- **A** zeroes the altimeter correction (README: no visible effect).
  - `altimeter_offset` [1E20] is added to the altimeter reading.
  - The routine at 0551 moves it by 1 at a time towards [1E22], which is named `takeoff_spot` in symbols.txt and is
    probably a pressure target.
  - A clears both.
- **0** sets magnetos = 5 with both switch bits off (README: no effect). The engine is off, and
  the panel's MAGS label shows "LN": index 5 runs past the label table.
- **F2 in reality mode** stops the engine (`engine_stop`) when the throttle was below 3E80h and
  `frame_counter & 3` = 0. So slamming the throttle open stalls the engine one time in four.
- **`-` / `=` in war mode** always change the radar zoom; the radios cannot be tuned in war mode.
- **C / N / T, then the second field.**
  - Pressing C or N again within about 1 s (`key_recent`, 18 ticks of 18.2 Hz) selects the
    fractional part. T steps through the 4 transponder digits (README: "press again for the next
    field"; this is the time limit).
  - KP8 / KP2 pressed within 8 ticks of the last elevator key step 8× as far. This is the key
    acceleration.
- **T in slew mode** copies the view attitude to the aircraft: pitch = -view_pitch,
  bank = -view_bank, heading = view_heading.
- **KP5 in slew mode** also sets the elevator to 0, the throttle and flaps to 4000h, and the
  slew rates to 0.
- **KP7 / KP1 / KP9 / KP3.** KP7 / KP1 also change `slew_rate_a` / `slew_rate_b`. KP9 / KP3
  change them in normal flight too, with no visible effect until slew mode.
- **Tab.** `cga_program_regs` runs with BX = 1Eh, left over from the dispatcher (2 × scancode).
  So it writes CRTC pairs from DS:001E, not the init table. It has no effect here.
- **Space outside war mode** sets `gun_burst` whenever the ammo count is nonzero. Nothing visible.
- **Enter in flight** does nothing (`enter_unhooks` is never set).
- **Keypad `.` / Del (53h)** runs `key_ignore` (redraws the trim indicator), except as part of
  Ctrl+Alt+Del. The brakes are on the `.` key (34h), as the README says.

## Moving input into C (for 3.21)

Here the scancodes still go SDL → `pc_key_event` → port 60h → IRQ1 → `int9_keyboard`. When the
main loop and timer are in C (3.21), the keyboard can skip the emulated path:

1. **Event queue.** `main.c` keeps the queue of XT make codes (break codes are dropped: the
   handler ignores bit 7). SDL's own key repeat, or the script's 500 ms / 10 Hz rule, gives the
   typematic repeats.
2. **Dispatch.** At the point of the frame where IRQ1 would have been taken, the C main loop calls
   `b_key_dispatch` with the scancode. There is no port 60h / 61h, EOI or IRET any more. Clearing
   `demo_mode` stays, as `int9_keyboard` does it.
3. **Reboot.** `key_dispatch`'s Ctrl+Alt+Del branch becomes a request to the front end to restart
   the game (the BDA warm-boot flag is then not needed).
4. **Editor.** `editor_key` keeps being set the same way. The editor's wait loops (3.16) can then
   wait on the queue in C instead of polling memory.
5. **Demo.** `demo_step` calls `b_key_dispatch` directly, as now.
6. **Timing.** Only the moment of delivery changes: once per emulated instruction now, once per
   main-loop step then. The 10,000-cycle spacing of `kbd_poll` and the hand-back logic go away.
7. **Handlers.** The handler bodies here already work on game state through `game/state.h`. Once
   no original code is left to call, the cycle accounting and `run_from()` can be dropped from
   them.

## Framework notes (for the coordinator)

- **Calls that never return.** `--verify` cannot check a call that leaves the program
  (Ctrl+Alt+Del jumps to F000:E05B). Suggestion: `run_original` could treat CS:IP = F000:E05B (or
  any far jump out of segment 0050 that is not an interrupt) as the end of the run, and compare
  state there. `NO_VERIFY` in `verify_campaign.py` could then go.
- **Shared helpers.** This is the fourth copy of `run_from` / `call` / `irq_due` / `entry_run` /
  cost tables (after 3.14, 3.16 and 3.17). A `src/natives/native_util.h` with these, the device
  snapshot (`DevState`, also in native.c) and a generic `gen_cycles.py` would remove the copies.
  `gen_keys_cycles.py` already reuses `gen_editor_cycles.py`'s harness.
- **Hand-back rate.** About 28% of keyboard interrupts hand back, because a timer tick or the next
  scancode falls within the handler's cycles (the indicator handlers take 1,500-4,000 cycles;
  KP* takes 29,000). Interruptible natives (see 3.16) would remove this.
