# 3.15 Game state in C

Natives stop addressing game variables by raw DS offsets and use named, typed accessors
generated from `docs/symbols.txt`. Game memory stays the only copy of the state: the original
code still runs for keyboard, editor, menus, sound, the main loop and the timer, so nothing is
shadowed in C variables.

## What was added

- **`tools/gen_state.py`** generates **`src/game/state.h`** (committed; the generator is the
  source of truth, `python tools/gen_state.py --check` fails if the header is stale). For every
  `var 0618:XXXX` symbol:
  - `#define GS_NAME 0xXXXX` (all symbols, also untyped ones), for tables, pointers and SI/DI;
  - `byte` / `word` / `dword` / `24-bit`: `gs_name(pc)` and `gs_set_name(pc, v)`;
  - `table`: `gs_name_b/_w(pc, i)` and `gs_set_name_b/_w(pc, i, v)` (byte i / word i);
  - `text`: `gs_name_ch(pc, i)` and `gs_set_name_ch(pc, i, v)`.
- **Signedness.** A word or dword is signed when its name is in the generator's `SIGNED` list
  (controls, binary angles, rates, forces, Q15 sin/cos, positions, radio offsets) or its
  symbols.txt comment contains `[signed]`. Everything else is unsigned. Converted natives cast
  where they used the other view, so the bits are unchanged.
- **Segment.** Accessors read and write `DS:offset` through `cpu_read8/16` / `cpu_write8/16`
  (`GS_SEG(pc)` = the live DS register), exactly as the replaced `[offset]` instructions
  address memory. DS is GAME_DS (0618) in normal operation, but not in every call: with
  accessors hard-wired to 0618, `clear_screen`, `obi_readout`, `control_coupling` and
  `wing_cl_offsets` mismatched in the user-mode sessions (they run with another DS from the
  editor / start-up paths). Tracing and the verify write log see every access.
- **Data model.** The header comment groups all symbols into blocks with units and formats:
  aircraft (position 16.16 with 256 m integer units, altitude byte fraction + word, angles
  10000h = 360 deg, airspeed V/109 kt, Q15 sin/cos), controls, flight model, engine, radios,
  panel, war, editor, view and scenery, system. Later subphases (3.21 main loop, phase 4) can
  build on it.

## Conversion

Mechanical (a one-off script, not committed): every call of a file's DS memory helper
(`rd16`, `rds`, `wr8`, `m16`, `dsr16`, `mem_read16(pc, ds, …)`, `cpu_read8(c, cpu_linear(ds, …))`,
`ds_read8`, …) whose offset is a literal or a local `#define` / enum naming a symbol was
rewritten:

- exact symbol and width → `gs_name(pc)` / `gs_set_name(pc, v)`;
- inside a table with a known extent → `gs_name_w(pc, i)` / `_b`;
- otherwise (another width, a byte of a word) → the helper call kept, offset written as
  `GS_NAME` or `(uint16_t)(GS_NAME + n)`;
- `flight_motion.c` writes keep `wr8/wr16/wr32` (they go through its undo log for
  `irq_hand_back`); only their offsets became `GS_*`. Its reads use the accessors.

Local offset `#define`s / enum entries that named a symbol were removed and their remaining
uses replaced with `GS_*`. Helpers and `ds` locals left unused were removed.

Files converted: flight_forces, flight_motion, gauges, radio, war, indicator, horizon,
scenery, transform, format, buffer, line, text (13 of the 17 area files; editor, keys, math
and test have no DS variables). About 640 accessor calls and 250 `GS_*` uses.

## Remaining raw offsets

About 100 call sites still use an offset with no symbol, mostly anonymous ones in gauges.c
(34: 03F9, 0403, 0418, 0550, 06AD/06AF, 0799-079B, 07D1-07DB, 0905, 094C, 1437, 19A0-19A8,
1B24, 1B28, 1E20, 208B/208D), scenery.c (19: 3164/3165, 3180, 31B5-31B9, 31CD, 31D4, 31DF,
3732-3736, 1F40), transform.c (13: 059B, 3143-3157 rotate outputs, 3168-316A), radio.c (12:
2071, 2085/2087, 31D8-31DC, 3662-370A print records), war.c (9), format.c (6: 2019-2032),
flight_forces.c / flight_motion.c (4 each: interior words of mass_constants, shear_tops,
wind_layers, mag pairs, 19A0 / 041B / 1ED3). They need their meaning worked out before naming;
offsets inside a symbol (table interiors, the high byte of a word) are written `GS_NAME + n`.
