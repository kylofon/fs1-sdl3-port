## Formats learned

- **`fmt_signed_dec` (11A9)** also prints. Its input is AX. It writes DS:[BX] = `' '` or `'-'`, then five
  digits at [BX+1..5], keeping leading zeros. -32768 (NEG overflows) takes a separate path that writes the
  literal `"32768"` and leaves DL untouched. Otherwise DL ends as the tens digit.
  - It does **not** return. It jumps into `print_str_dim` at 1233 with CX = 8888h and
    ES = [view_buf_seg], so SI must point to a whole print record and BX points into that record.
  - The native therefore also contains that print tail. Characters 20h..7Fh are printed (SUB AL,20h / JGE).
    The five font displacements are read from the self-patched `MOV AX,[BX+disp]` instructions at
    1247/1252/125D/1268/1273 on every call, so it follows the runtime font address.
  - Its only caller is `slew_readout` (1150): N/E from `editor_values` 2050/2052 and, when [0418] is set,
    the high bytes of `pos_north`/`pos_east`.
- **`fmt_course_digits` (1508)**, previously `sub_1508`: AL is a course in 2° units. It returns
  DL = `'0'` + AL/50, AL = tens and AH = units of (AL mod 50)·2, all as ASCII. DH is kept. `sub_14C9`
  calls it twice (OBI course and course − 90°) to build the three-digit text at `nav_freq+10` and 07C1.
- **`fmt_dec4` (3555)**, previously `sub_3555`: AX 0..32767 gives CL = thousands, CH = hundreds,
  AL = tens and AH = units (ASCII). It leaves DX = AX mod 100 and BP = 100. `sub_3553` (XOR AH,AH) falls
  through into it, and the native at 3555 handles that path too, because the return address is the same.
  A negative AX would make the original's DIV fault (INT 0). The native does not model this, and no caller
  passes a negative value: war ammo is clamped at 0, and the score at 1E57 is 0..10000. Callers: war
  score/ammo (3575, 35A0), plus the unexecuted 4FC0..505F block.
- **Editor 24-bit values.** `editor_value` is at 2012..2014 (24-bit LE). `editor_digits` is at 202C..2031:
  six ASCII digits, most significant first. The powers of ten 100000..1 are split by byte: low at 2036,
  mid at 203C, high at 2042.
  - `editor_digits_to_bin` adds each digit's power ((d & 7Fh) − '0') times, with a byte counter. A
    non-digit is not rejected: a space counts F0h times. It returns CX = 0 and DI = 6. AL is the last
    high power byte added.
  - `editor_bin_to_digits` first calls `sub_36F4`: BX = word [28E4 + editor_row]. The row is not doubled.
    BX is also stored at 2020h.
    - It blanks ES:[BX+0Ah..14h] (every other byte, text mode). Then it writes the digits left-aligned
      with leading zeros dropped, finding each one by repeated 24-bit subtraction until bit 23 is set.
    - `editor_value` is left as the remainder (0). 2019h = digits written, 201Ah = last digit and
      2032h = next cell.
    - The native also writes the CALL's return address (3893h) at SS:SP−2, as the original does.
      `--verify` compares that stack byte.

## Proposed symbols (symbols.txt syntax)

    code 0050:1508 fmt_course_digits     ; [code] AL (2-degree units) -> DL hundreds, AL tens, AH units (ASCII)
    code 0050:3553 fmt_dec4_byte         ; [code] AH = 0, then fmt_dec4
    code 0050:3555 fmt_dec4              ; [code] AX 0..32767 -> CL CH AL AH = 4 ASCII digits
    var  0618:2012 editor_value          ; [code] 24-bit LE value being converted
    var  0618:202C editor_digits         ; [code] 6 ASCII digits, most significant first
    var  0618:2036 pow10_lo              ; [code] 100000..1 low bytes; mid at 203C, high at 2042

`fmt_signed_dec`'s comment could add: "...then prints the record at SI (tail-jumps into print_str_dim)".

## Not replaced

- The `aam` two-digit conversions at 1526 (clock seconds), 1543 (minutes) and 1556 (hours) are inline
  in `sub_151C`/`sub_1540` and are not callable routines.
- `com_tune` (ASCII → BCD) belongs to 3.12 (radio).

## Extra coverage (not in the campaign)

The campaign never reaches the negative paths of `fmt_signed_dec` (11B3, 1206). They were exercised with
`tools/trace_campaign.py`'s `editor_set` helper:

- slew on (`editor_set(300, 3, 1)`)
- then a field set to 40000 and another to 32768
- `build/fs1 --frames <end+600> --verify fmt_signed_dec --keys "<script>"`

Slew readout values seen and verified:
- fields 9 then 10: 8000h (-32768), 0 mismatches over 678 calls
- fields 11 then 12: 9C40h (−25536), 0 mismatches over 420 calls

The key script was generated like this (run from the repo root):

    import sys; sys.path.insert(0, "tools")
    from trace_campaign import editor_set
    k = ["120:A", "180:B"]
    ks, f = editor_set(300, 3, 1); k += ks
    ks, f = editor_set(f, 9, 40000); k += ks    # or 11
    ks, f = editor_set(f, 10, 32768); k += ks   # or 12
    # build/fs1 --frames f+600 --verify fmt_signed_dec --keys ",".join(k)

## Notes for the framework

- A native for a routine that tail-jumps into shared code (11A9 → 1233) has to reimplement the shared
  tail. A framework option to "run the original from address X after the native" would avoid duplicating
  `print_str` here. Once 3.9 has a C `print_str`, `fmt_signed_dec` could call it.
