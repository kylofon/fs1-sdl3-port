# 3.1 Maths helpers

Natives in `src/natives/math.c`. Shared C helpers in `src/natives/fixmath.h`.

## Natives

| Name | Address | Enabled | `.cycles` | Campaign calls | Mismatches |
|---|---|---|---|---|---|
| `sincos` | 0050:45C0 | yes | 597 + path | 19,485 | 0 |
| `sin_quadrant` | 0050:45FD | yes | 253 | 0 with `sincos` on (see below); 38,970 with `--native-off sincos` | 0 |
| `div_q15` | 0050:1BEE | yes | 54 + path | 5,294 | 0 |

`python3 tools/verify_campaign.py` prints OK: zero mismatches in all 14 sessions.

**Why `sin_quadrant` gets no calls.** Its only callers are inside `sincos` (calls at 45D2, 45E2 and 45EC,
plus the tail `JMP` at 45DF). When the `sincos` native is on, the original `sincos` never runs, so nothing
reaches 45FD. During a verify run, natives reached from original code run as original code. The
`sin_quadrant` native is checked with `python3 tools/verify_campaign.py sin_quadrant -- --native-off sincos`,
which gives OK, 38,970 calls and 0 mismatches. It stays enabled, so it still applies if `sincos` is turned off.

**Shadowing.** `test_passthrough` (test.c) has the same address as `sin_quadrant`. When both are enabled,
`hook_index` keeps the later entry, which is math.c's. To exercise the framework test, use:
`verify_campaign.py test_passthrough -- --native-off sincos --native-off sin_quadrant`. That gives OK
with 38,970 calls.

**Flags.** `.flag_mask = 0` for all three. Every call site (161E, 162C, 196A, 2FA7, 4628, 463B, 4666 for
`sincos`; 17E2, 1B26, 1B37, 1B48 for `div_q15`) overwrites the flags before it reads any. The natives still
compute CF/PF/AF/ZF/SF/OF exactly as the CPU core does for the last flag-setting instruction.

**Cycles.** Each original's cost depends on its path. `.cycles` is the cheapest path. The native adds the
difference for the path it actually takes, so the emulated timeline matches the original exactly. Demo
and keyboard screenshots with the natives on and off are byte-identical. The costs below were measured on
the CPU core:
- `sincos`: 616 for 0..4000h, 597 for 4001h..7FFFh, +92 for negative angles (the inner path then follows
  -angle), and 681 for 8000h.
- `div_q15`: CX = 0 gives 54 (DX < 0) or 66. Otherwise, indexed by (dividend sign, divisor sign) as
  saturated/divided: (+,+) 84/226, (+,-) 94/241, (-,+) 122/269, (-,-) 115/257.
- `sin_quadrant`: always 253.

**Stack.** The original `sincos` leaves the return addresses of its inner CALLs below SP: 45EF or 45D5,
and also 45FA one word further down for negative angles. The verifier compares those bytes, so the native
writes them too.

**Exhaustive check (outside the campaign).** A scratch harness (not committed) ran the original code on
the CPU core against each native, comparing all registers, the arithmetic flags, the stack bytes and the
cycles:
- `sin_quadrant`: every BX in 0..4000h
- `sincos`: all 65,536 angles
- `div_q15`: 2,000,000 random and edge-case inputs, which covers every path
- `fx_div_q15`, `fx_sin`, `fx_cos` and `fx_mul_q15` against the same results

All were identical. The campaign itself reaches only 16 of `div_q15`'s 36 instructions.

## Semantics learned

- **sine_table (DS:3381) is a cosine quarter wave.** T[0] = 7FFFh, T[64] = 5A82h, T[128] = 0, and T[129] =
  -401 is a guard word. It is read at x = 4000h but multiplied by 0. `sin_quadrant(x)` returns cos(x). That
  is why `sincos` calls it with 4000h - angle to get the sine and with angle to get the cosine. The table
  is all zeros in `boot_mem.bin` (right after the load stream) and holds data at run time. No traced
  instruction writes it (`vars.txt` W: 0), so it most likely arrives through a disk read, which the
  verifier doesn't track. Helpers that read it are valid only once the game is running.
- **sin_quadrant**: index = (x >> 7) words, frac = x & 7Fh, result = T[i] + bits 7..22 of frac * (T[i+1] - T[i])
  (signed). It leaves BX = 2i, SI = T[i], DI = T[i+1] - T[i], and DX = the high word of the product shifted
  left 1.
- **sincos**: BP = the angle. For a negative angle it recurses on -angle, so BP ends as -angle, and 8000h
  becomes 7FFFh. The negation only flips AX = sin, and CX = cos is taken from the recursion. The other
  registers come from the last `sin_quadrant` call. In 4001h..7FFFh, CX = -T(8000h - a) and AX = T(a - 4000h).
- **div_q15** (DX:AX = n, CX = d), exact behaviour:
  - d = 0: DX = 7FFFh if DX >= 0 (only the sign of the high word is tested), else 8001h. Nothing else changes.
  - Otherwise |n| and |d| are taken. A negative n is negated as a 32-bit value and sets BX = 0. CX is left
    as |d|, and the result sign is sign(n) xor sign(d).
  - If (signed) hi(|n|) >= |d|, it saturates to DX = 7FFFh, or 8001h for a negative result. AX is left as
    lo(|n|).
  - Otherwise `DIV`: AX = |n| / |d| (unsigned), and DX = AX >> 1, negated for a negative result. This is
    Q15 when |n| < |d| << 16. The rounding is toward zero, and the >> 1 comes after the unsigned divide.
  - **Latent fault:** n = 80000000h with |d| < 8000h passes the signed compare (hi = 8000h is negative), and
    then its `DIV` overflows with INT 0. The native handles this by restoring the state at the `DIV` (IP =
    1C15h or 1C20h, return address still on the stack) and returning to the original code there, so the
    fault happens exactly as in the original. It never occurs in the campaign.

## fixmath.h (for later subphases)

All helpers are `static inline` and include `native.h`. The table is read from game memory and is not
embedded.

| Helper | Result |
|---|---|
| `fx_sin(pc, angle)` / `fx_cos(pc, angle)` | Q15 sin/cos of a binary angle, identical to `sincos` AX/CX (uses DS = 0618) |
| `fx_sincos(pc, angle, &s, &c)` | both at once; either pointer may be NULL |
| `fx_sincos_regs(pc, ds, angle)` | every register `sincos` leaves, for natives that inline it |
| `fx_quadrant_regs(pc, ds, x)` | every register `sin_quadrant` leaves (x = 0..4000h) |
| `fx_mul_q15(a, b)` | DX of `IMUL; SHL AX,1; RCL DX,1` = (a*b) >> 15, floor; 8000h*8000h = 8000h |
| `fx_mul_q15_32(a, b)` | the full DX:AX of that idiom |
| `fx_div_q15(n, d)` | DX of `div_q15` (int32 dividend, int16 divisor), saturating as above |
| `fx_div_q15_faults(n, d)` | true for the one input where the original faults; `fx_div_q15` then saturates by the result sign |

A native that calls these instead of the original routine also has to reproduce the clobbered registers
(use the `*_regs` variants), the stack bytes below SP and the cycles, if its own caller can observe them.

## New symbols (docs/symbols.txt syntax)

    code 0050:45C0 sincos                ; [code] BX = angle -> AX = sin, CX = cos (Q15); BP = angle (or -angle, 7FFFh for 8000h); BX DX SI DI from last sin_quadrant
    code 0050:45FD sin_quadrant          ; [code] BX = 0..4000h -> AX = cos(BX) (Q15) from sine_table + linear interpolation; misnamed: the table is a cosine
    code 0050:1BEE div_q15               ; [code] DX:AX / CX signed -> DX = (|n|/|d|)>>1 signed; saturates 7FFFh/8001h; CX=0 -> by sign of DX; faults (INT 0) for 80000000h
    var 0618:3381 sine_table table       ; [code] Q15 cosine quarter wave, 129 words T[0]=7FFFh..T[128]=0 + guard word; filled at run time

## Framework notes (no change made)

- When two enabled entries share an address, `rebuild_map` silently keeps the last one. A warning would help.
- A native that needs to charge path-dependent cycles adds the difference to `pc->cpu.cycles` itself. A
  documented helper (for example `native_add_cycles`) or a per-call cycles return value would make this
  explicit.
- `scripts/cloud_setup.sh` assumes Linux. On this Windows host, `cc` failed inside Git Bash, so the build
  and analysis steps were run from PowerShell with the same commands. The image download worked through gh.

## For the user to test

Normal flight in every area, including steep banks, inverted flight and loops: these exercise `sincos`
with negative angles and the 8000h edge case. Also check slew and war mode. There should be no visible
difference, because the timeline is cycle-exact.
