# 3.13 Flight model: forces

Area file: `src/natives/flight_forces.c`. No shared header changes.

## Natives

All four are enabled by default and cycle-exact. Each one adds the emulated cycles that the original takes on the path it ran, using the cpu8086.c model. A temporary check in the verifier, not committed, compared the charged cycles with the original's on every verified call. There were 0 differences.

| name | address | campaign calls | mismatches | `.cycles` | flag_mask |
|---|---|---|---|---|---|
| `flight_forces` | 0050:1610 | 1756 | 0 | 54 (paused or slew) + path | 0 |
| `fix_loop_over` | 0050:18CE | 0 (2918 with `--native-off flight_forces`) | 0 | 60 (no mirror), 115 (mirror) | 0 |
| `control_coupling` | 0050:10B6 | 172 | 0 | 856 | 0 |
| `wing_cl_offsets` | 0050:10EF | 46 | 0 | 138 | 0 |

- **Gate.** `python tools/verify_campaign.py` with every native on main plus these prints OK.
- **fix_loop_over gets no calls with everything on.** Its only callers are inside `flight_forces`. It was verified separately with `verify_campaign.py fix_loop_over -- --native-off flight_forces`, which gives OK.
- **Flags.** No caller tests flags afterwards: the int8 handler, the key handlers and the JMP/NEG after `fix_loop_over` all overwrite them first. So `.flag_mask = 0`, and the natives don't compute flags.
- **Inlined sincos and div_q15.** `flight_forces` computes them in C with `fixmath.h` (`fx_sincos_regs`, `fx_div_q15`). It reproduces their registers, their cycles (formulas from math.c) and the stack words they leave behind.
- **Stack words below SP.** The native also writes the return addresses and the pushed word that the original leaves below SP: 1621/162F with the sincos inner returns, 17E5, PUSH DX, then 18CB or 18F6.
- **Registers.**
  - `flight_forces` leaves:
    - AX = pitch step
    - BX/SI/DI/BP from sincos(bank)
    - CX = |airspeed|
    - DX from `fix_loop_over`
  - On the paused or slew path, only AL changes (AL = paused OR slew).
  - `control_coupling` and `wing_cl_offsets` leave AX/DX = the left/right CL offsets.

## Semantics learned (flight_forces)

Products use these IMUL idioms (`mul_shl`, `mul_hi` and `mul_mid` in the C):
- **Q15:** `imul; shl/rcl` once.
- **×8:** three shl/rcl pairs, used for the AoA and the per-wing lift.
- **High word only:** used for accel and the control-coupling terms.
- **>>8:** `mov al,ah; mov ah,dl`.

1. **Trig.** It computes sin and cos of pitch and bank (089A/0840/089C/0844). It also stores cos²(bank) with the sign of cos (0850).
2. **Angle of attack.**
   - 0836 = V · [0862] · 8, where [0862] is the elevator times [08DA].
   - V is capped at 1E00h. The cap tests the sign of AH − 1Eh (`cmp ah,1Eh; js`), so AH ≥ 9Fh would pass uncapped. That is a quirk and is never reached.
3. **Lift coefficient.** CL_aoa (087C) = AoA · [08F0].
   - CL_left = CL_aoa + [087E]. It is forced to 0 when [1E83] == 1, which means the left wing was shot off in war mode.
   - CL_right = CL_aoa + [0880].
4. **Stall.** When AoA > 1F40h or AoA ≤ E4A8h (signed), both CLs become 0, `sound_state` = 1 (stall horn) and [0558] = 1. Otherwise [0558] = 0.
5. **Lift.**
   - V² (08AE) is computed with an unsigned MUL.
   - Per-wing lift is 0886/0888 = V² · CL · 8.
   - lift (0884) = (left + right) · air_density.
   - The roll moment (0892) = (left − right) << 2.
6. **Weight split.** 08A0 = W·sin(pitch) and 0848 = W·cos(pitch).
7. **Normal force.** 08A6 = lift · cos²(bank) − W·cos(pitch).
8. **Drag.**
   - The coefficient (0874) = CL_l² + CL_r² + [0872] (slip) + [0866] (flaps).
   - Scaling: 0876 = 0874 · [08CE], then 0878 = 0876 + [083E] (gear).
   - drag = 0878 · V² + W·sin(pitch), plus [08EC] while V ≠ 0.
9. **Acceleration and 1/V.**
   - accel (085E) = hi([088C] · (thrust − drag)).
   - 08AA = div_q15(0280:0000, V), i.e. 1/V, which saturates at low speed.
10. **Pitch acceleration.** 08AC = 1/V · normal force.
11. **Turn rate.**
    - turn_rate = [08E6] · ((1/V · lift·sin(bank)) << 6) + (V · [084C]) · 8.
    - On the ground with V ≠ 0, it is replaced by rudder >> 3 (nosewheel steering).
12. **Pitch rate.** pitch_rate = [088E] · 08AC. On the ground it is clamped to ≥ 0.
13. **Airspeed integration.** airspeed += accel + (pitch_rate·[08E2] >> 8).
    - On overflow, or a result above 6400h, airspeed becomes **64xxh**: AH = 64h, and AL stays the low byte of the increment. That is a quirk.
    - A negative result gives 0.
14. **Pitch integration.** pitch += pitch_rate + (accel·[08E8] >> 8).
    - A negative pitch is negated around `fix_loop_over`.
    - `fix_loop_over`: if pitch & C000h, then pitch = 8000h − pitch, bank += 8000h and heading += 8000h.

**control_coupling.** It computes the cross-control term X (084A) = aileron/2 − rudder/2, then:
- slip drag (0872) = hi(X·[08E4])
- slip yaw (084C) = hi([08D2]·X)
- roll term (08A2) = hi([08D4]·X); `flight_integrate` reads it
- left-wing CL (084E) = hi([08D0]·X)

It then falls into `wing_cl_offsets`:
- 087E = [0882] (flaps) + [08C8] (CL0) + [087A] (aileron) + [084E]
- 0880 = [0882] + [08C8] − [087A]

**Not reached:**
- **The loop-over mirror in `fix_loop_over` (18D8).** Full up elevator stalls the wing (AoA > 1F40h) long before the path passes 90°. A dive to 184 kt followed by a pull still stalled. A real loop may not be possible in this flight model.

These paths are straight transliterations, 3 to 5 lines each. The editor field numbers used by `editor_set` (10 and 14) did not set altitude and airspeed in my runs. In the "loop" probe, the aircraft started on the ground at N=D770. That should be checked against the editor page layout.

## Record and replay

Three scripts (take-off and climb, steep banks, flaps and gear) were each run with `--dump-on-exit`, with these four natives on and then off. Every other native on main stayed on in both runs, except as noted below.

**Result: identical.** With `scenery_interp` and `draw_scenery` off in both runs, the two runs end bit-identical:
- north, east and altitude
- heading, pitch and bank
- airspeed
- the total emulated cycle count

For example, take-off: N=31E00FB, alt=FEFA, V=21D7, 502,241,220 cycles in both. So the forces natives add no drift at all.

**Finding: drift from the 3.8 scenery natives.** With every native on main enabled, the same scripts end at different positions between runs. For example, after take-off the altitude is 4F18 vs 4E8D, and the steep-banks heading is 3B0F vs 3F20. The emulated time also grows about 5x:
- take-off, 6000 frames: 2.82e9 cycles, against 0.49e9 with all natives off
- 600 frames at the menu: 219M cycles, against 51M with every native off or with only `scenery_interp` and `draw_scenery` off

The cause is `scenery_interp`/`draw_scenery`, not 3.13. Each frame's cycle budget is relative to where the previous frame overshot, so the extra cycles they charge per call accumulate. Scripted keys then land at different points in the flight, and that alone makes the run diverge. Turning off any one other native leaves the count at about 219M. Please check the 3.8 cycle accounting.

## Problems

- Building from Git Bash fails, because `cc1` can't load its DLLs. Building from PowerShell with `C:\msys64\mingw64\bin` first in PATH works.
- The scripted runs are slow, about 1 minute per 8000 frames, so the probes were kept short.
