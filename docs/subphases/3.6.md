Coverage notes:
- `project_dot` (3D1A) is only reached in the war session, and there it always takes the
  early exit (point behind or outside the view). Its plot and capture code is shared with
  `project_dot_regs`, whose plot path is verified in user mode 3 (48 dots, 888 cycles
  including plot_pixel_es). The capture branch (3D76, capture_mode = FF) is never
  executed in the traces (marked S), so it is not verified.
- The clipping divide-overflow path (see below) occurs regularly and is verified.
- Screenshots differ from `--native-off` runs after a while because the routines' cycle
  costs vary per call (timeline drift), as allowed for this subphase.

The intersection helpers 4A82 and 4AAB are not separate natives: their only callers are
4AF7 and 4BCD, so as natives they would never be reached (0 calls). They are inlined into
`clip_point()`.

No caller looks at the flags these routines return (every call site is followed by MOV,
CALL, PUSH/POP or a memory compare), so no `flag_mask` is declared.

## Formats and findings

- **Eye-space points.** Point 1 = 310F/3111/3113 (x, y, z), point 2 = 311B/311D/311F, with
  copies at 3127.. (point 2 saved) and 3133.. (move-to start). The frustum is x = ±z,
  y = ±z (90° square), z forward.
- **Outcode** bits: 8 = x < -z, 4 = x > z, 2 = y < -z, 1 = y > z.
- **build_view_matrix**: AX/CX of `sincos` for view_angles[0] (pitch-like), [2] (bank-like),
  [4] (heading-like) are kept at 3143/3149, 3145/314B, 3147/3157; products at 314D..3155.
  Matrix rows (as used by `rotate_point`): x' = m[0]x + m[6]y + m[12]z (30FD, 3103, 3109),
  y' = (30FF, 3105, 310B), z' = (3101, 3107, 310D).
- **rotate_point** returns x in BX:SI, y in CX:DI (doubled), z in DX:BP (halved; bit 31 is
  replaced by bit 30 in x and z). Unless bit 0 of `[3380]` was set (the byte is shifted
  right on every call, so it is a one-shot bit queue), the three 32-bit values are shifted
  left 3 bits at a time (with a 1 entering SI's bottom bit on each round) until one high
  byte leaves -4..3. Callers (47EA, 4801) keep the high words.
- **world_to_eye_delta**: BX points at a scenery record (opcode byte, then x, y, z words).
  When bit 0 of `[315D]` is set (again a shift-right bit queue, set by `inc [315D]` at 3D8A
  and 3DAF) y comes from `[315B]` instead of the record. On a 16-bit overflow of a
  difference, all three are divided by 32 (the overflowed one recovered through CF;
  for an x overflow the others are computed as (a/2 - eye/2)/16). Otherwise large
  values are halved once or twice and small ones multiplied by 8 until a high byte leaves
  -4..3. `[3162]` = 0Ah is set on the normal path (the clip loop counter).
- **Clipping step** (4AF7 for P = point 1, 4BCD for P = point 2, Q = the other one):
  plane from P's outcode (`al <= 3` -> y planes, bit 0 picks y = z / y = -z; else x planes,
  bit 2). With a = the clipped coordinate, o = the other one:
  BX = denominator (aP + zP - aQ - zQ, or aQ + zP - aP - zQ), DX = zP ± aP, CX = oQ, SI = oP,
  t = (DX:0 >> 1) / BX (IDIV, Q15), oP += t(oQ - oP), zP += t(zQ - zP), aP = ∓zP. The
  helper then shifts DX:DI and SI:CX left together while both high bytes are in -16..15
  (at most 16 times); the result's high words are kept. `clip_project_line` (40C8)
  loops this at most `[3162]` times per end.
- **project_dot**: nothing unless z > 1 and |x|, |y| < z (ones' complement for negatives).
  q = (v << 15) / z, s = ((q >> 8) * scale * 2 >> 8) + centre (signed bytes, proj_params
  3167..316A). Plots with a tail JMP to `plot_pixel_es` (AH = sx, CL = sy), or with
  capture_mode set writes FE, sx, sy at `[30C6]` and adds 3.
- **select_view_angles** handlers at `[059B]` (table at 05A1, set by key_repeat_accel):
  4737 ahead, 474A ahead +22.5° heading, 47B5 ahead -22.5°, 4755 right (a0 = -bank,
  a2 = pitch - 300h, heading + 90°), 479A left, 4770 rear-right (+135°, pitch/bank
  negated), 478A rear, 4792 rear-left (+225°), 47C1 down (pitch + 90°). 474A, 4755, 4770,
  4792 and 47B5 are code the disassembler shows as data. The native implements these and
  runs any other handler as original code.

## Interfaces left for later (draw_line / plot_pixel)

- `clip_project_line` 0050:40C8 (not replaced): uses [315E]/[315F]; both 0 -> project both
  points (4CA3/4D18, the latter the same divide as project_dot) and `draw_line`
  (BX,BP = x0,y0, SI,DI = x1,y1); `[315E] & [315F]` nonzero -> rejected; otherwise calls
  `clip_p1_plane` then `clip_line_planes` up to `[3162]` times each. Clears `[3163]`.
- `project_dot` ends with a JMP to `plot_pixel_es` 0050:5660 (owned by 3.3). The native
  computes the projection, then runs plot_pixel_es as original code (natives off) until it
  returns to project_dot's caller; its cycles are charged by that run, and `.cycles` covers
  only the projection. So 3.3's plot_pixel native is not used from here; once 3.3 is
  merged, the tail can call its C function directly.

## Notes for the coordinator

- The sin/cos helpers (`sin_quadrant`, `sincos_q15`) are private copies of 45FD/45C0 that
  also write the return addresses the original's CALLs leave below SP (--verify compares
  them). They can be swapped for `src/natives/fixmath.h` (3.1) after merge if that keeps
  those stack writes.
- Paths handed back to original code instead of being reimplemented:
  - **Clipping divide overflow.** When Q lies exactly on the plane, t = 1.0 does not fit
    the IDIV, which raises INT 0. The game's handler `int_4DC6` (installed by 6254)
    saturates AX to +7FFF / -7FFF by the sign of DX^BX and IRETs; it also leaves FLAGS,
    CS, IP below SP. This happens often (hundreds of times per session), so the native
    runs the intersection helper as original code in that case.
  - A point exactly at the eye makes world_to_eye_delta loop forever at 497E (all three
    deltas 0); the native jumps there, so the game hangs exactly as before.
  - An unknown `[059B]` view handler is run as original code.
- Framework suggestion: a `native_call_original(pc, off)` helper in native.c (with hooks
  off) would replace the private `run_original_until()` here.
- Setup on Windows: `cloud_setup.sh` fails in Git Bash because MinGW gcc does not work
  without `C:\msys64\mingw64\bin` first in PATH; built from PowerShell instead.
