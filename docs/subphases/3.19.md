# 3.19 Sound

Area file: `src/natives/sound.c`. Cost table: `src/natives/sound_cycles.h`, generated by
`tools/gen_sound_cycles.py`. Check of the speaker output with the natives on and off:
`tools/audio_compare.py`.

Part A replaces the sound routines and the timer interrupt with natives. Part B describes the
sound model, so that 3.21 can generate the sound from game state with SDL audio, without the
emulated PIT and speaker.

## Natives

| name | address | campaign (`verify_campaign.py`) | war sessions (`war_sessions.py`) |
|---|---|---|---|
| `int8_timer` | 07A0 (IRQ0, `.far`, IRET) | 181,190 / 0 | 367,726 / 0 |
| `sound_update` | 087F, with the table handlers and 0922 | 1,131 / 0 | 3,251 / 0 |
| `speaker_tone` | 0944 | 0 / 0 | 120 / 0 (bomb whistle, `war_bomb`) |

Counts are calls / mismatches. In the campaign row, every native is on and verified.

- **`speaker_off` (3B29)** was already a 3.16 native (editor.c), so it is not duplicated here.
  `sound_update` calls it through `native_call()`.
- **The PIT programming at 0922** is a tail of `sound_update`, reached by jumps from the engine
  and guns handlers. No CALL reaches it, so it is part of the `sound_update` native, not an entry.
- **`speaker_tone` coverage.** No campaign session stalls, drops a bomb or touches down while
  sound is on, so it gets no calls there. The `war_bomb` session covers it through
  `int8_timer`'s whistle path. Other untested paths:
  - the stall horn (state 1) and touchdown click (state 8) handlers of `sound_update`;
  - the `rpm_deficit` ≥ 1 branches;
  - the clock's minute and hour carries.
- **Implementation.** Same method as 3.16 and 3.18:
  - The routines are transliterated on the emulated registers, with the stack words of CALL and PUSH.
  - Cycles are charged per original instruction from the cpu8086.c cost table, so a call costs
    what the original costs.
  - Calls out (`atis_tick`, `flight_forces`, `demo_step`, `speaker_tone`, `speaker_off`, and an
    unknown table target) go through `native_call()` or are single-stepped as original code.
  - `int8_timer` reads the ADD immediate at 07BC from code memory. `sound_update` patches it
    (self-modifying code).
- **Port I/O** goes through `pc->cpu.bus.in8`/`out8`, so pc.c's PIT, port 61h and speaker log
  see it. The clock is advanced instruction by instruction, and an OUT happens 2 cycles into its
  instruction, as in cpu8086.c. So the speaker events have the original's cycle stamps.
- **Interrupt hand-back** (as in 3.18). If the timer or the keyboard falls due within a native
  call, its writes are undone, the device state is restored, and the original runs instead.
  `int8_timer` is also handed back when IF is set at its EOI. `atis_tick` draws through
  `blit_or`, which ends with STI, so the original can take a pending IRQ between the EOI and the IRET.

### A framework issue (worked around in sound.c, not fixed in pc.c)

pc.c advances the PIT only after each CPU step, and a native is one step.

- In the original, a reload (the second byte written to port 40h or 42h) starts counting down
  from the reload instruction's step.
- In a native, the count would also lose the cycles before the OUT.

`pit_reloaded()` in sound.c adds those ticks back to `pc->pit[n].count`. The count is measured
from the start of the outermost native step, with `pit_cycle_frac`.

Without this, IRQ0 drifts by up to the routine's length every time `sound_update` reprograms
channel 0, which is several times a second. This is the only direct write to device state.

A cleaner fix would be a pc.c hook that native code calls to advance the PIT to the current
cycle, for example `pc_sync_devices(pc)`. That hook would also let any native do port I/O at
exact times.

### Gate

- `python tools/verify_campaign.py` (all natives on): **OK**.
- The build has no warnings.
- `python tools/audio_compare.py` runs `demo`, `flight_keys` and `war` with all natives on, and
  again with `int8_timer,sound_update,speaker_tone` off. It compares three things:
  - **Final screenshots:** identical in all three sessions.
  - **Speaker event logs** (cycle, port 61h, channel 2 reload): identical in `demo` (10,104
    events) and `flight_keys` (8,238). In `war`, 1 of 7,388 events differs, by 5 cycles:
    `int9_keyboard`'s port 61h acknowledge pulse at frame 400. See "Frame boundaries" below.
  - **Audio rendered from the events** with pc_speaker_render's model on one global sample grid:
    identical in all three sessions (5 cycles is far below one 108-cycle sample).
- **Frame boundaries.** main.c injects scripted keys and renders audio between frames. A frame
  ends at the first step boundary past its cycle budget, and a native is one step. So:
  - a key is latched 5 cycles later after an `int8_timer` native than in the middle of the
    original;
  - the audio as played, rendered per frame, can shift an edge by one sample.

  This is the known framework limitation from 3.3 and 3.14, not a native error. The verify
  write logs and the screenshots are unaffected. The tool reports the as-played comparison for
  information.

## Part B: the sound model

All sound is one bit, port 61h:
- **bit 0** gates PIT channel 2;
- **bit 1** drives the speaker. The output is channel 2's square wave AND bit 1 when bit 0 is set,
  and plain bit 1 otherwise. pc.c renders the square wave whenever both bits are set.

There are three sources:
1. **The engine** toggles bit 1 from the timer interrupt. Its pitch comes from the rate of IRQ0
   itself.
2. **Channel 2 tones**, through `speaker_tone`: stall horn, bomb whistle, touchdown click, and
   the engine roughness buzz.
3. **The sound-off switch** (`editor_values[0]`, editor "Sound").

### Clocks

- **IRQ0 rate.** PIT channel 0 divisor `D = (19h − a) · 100h`, with `a = max(1, engine_rpm >> 2)`
  (`engine_rpm` = [1DC0], a byte). IRQ0 runs at `f0 = 1193182 / D` Hz.
  - `engine_rpm` moves one step per call toward `rpm_target` [1DC1] (`engine_rpm_step`, 2EEC).
    `rpm_target` comes from `rpm_by_power` (16..58 by power) or `rpm_windmill` (by airspeed),
    and is 5 when the engine is stopped.
  - So `a` = 1..14, D = 1800h..0B00h, and **f0 = 194.2 Hz** (rpm < 8: stopped or idle) up to
    **423.7 Hz** (rpm 56..58: full power).
  - Exception: the guns handler writes D = 12xxh, where the low byte is the port 61h value read
    on entry, normally 00h..03h. That gives about 259 Hz.
- **The slow tick.** Every IRQ0 adds D to `pit_accum` [054B] (the immediate at 07BC, patched with
  D). The slow path runs on a carry or a signed overflow, i.e. each time the sum crosses 8000h or
  10000h. That happens twice per 65,536 PIT clocks: **36.4 Hz, whatever D is**.
  - `atis_accum` [0542] += `comm_rate`; on a carry, `atis_tick` runs (except while
    `scenery_loading` [0419] = 1).
  - `tick_phase` [0555] toggles. Every second slow tick (**18.2 Hz**):
    - `tick18`++, `key_recent`--;
    - the bomb whistle step;
    - `ff_divider` [0556] counts 3..1. At 0 (**6.07 Hz**): `ff_ticks`++, `flight_forces`, the
      **engine pattern restart**, and `demo_step` in demo mode.
    - `clock_frac` += 0E11h; a carry is one game second (65536 / 0E11h = 18.2 ticks).
- **`sound_update` (087F)** runs from the main loop, once every two iterations (odd phases). Its
  rate depends on the frame rate, a few times per second.

### Engine: the bit pattern

On every IRQ0, `spk_pattern` [0543] is rotated left by one. If the bit that rotates out (the old
bit 15) is 1, port 61h bit 1 is **toggled** (XOR). A pattern of 16 bits repeats every 16 ticks.

- **Running engine:** `engine_sound` [1DD6] = A140h (set at 2D75 when the engine starts, 0 from
  `engine_stop`). Bits 15, 13, 8 and 6 are set, so the toggles fall at ticks 0, 2, 7 and 9 of each
  16. The level is high 2 ticks, low 5, high 2, low 7. Two narrow pulses per 16 ticks give a buzz
  with fundamental f0/16 (12.1–26.5 Hz), a strong f0/8 component (24–53 Hz), and harmonics up to f0.
- **Stopped engine:** pattern 0, so there are no toggles and the engine is silent.
- **Guns** (state 3): pattern 0009h. Toggles at ticks 12 and 15 give a 3-tick pulse every 16
  ticks, a 16 Hz rattle at D = 12xxh.
- **Restart (6.07 Hz).** If `spk_restart` [0547] AND sound_on, then `spk_restart`-- and
  `spk_pattern` = `spk_reload` [0545]. In state 0, `sound_update` sets `spk_reload` =
  `engine_sound` and `spk_restart` = 1 on every call. So the pattern phase is reset 6.07 times a
  second. f0/6.07 is not a multiple of 16, so the reset gives a slight flutter at about 6 Hz.
  `editor_apply_state` sets `spk_restart` = 1 too. Entering the editor clears it (3B0D) and calls
  `speaker_off`.
- **The level reset by `sound_update`.** The engine handler writes port 61h on every call:
  - with `rpm_deficit` = 0, bits 0 and 1 are cleared, forcing the level low;
  - otherwise both are set (see below).

  Because a forced low can come at a high moment, the pulse polarity can flip at the
  `sound_update` rate (a soft click).

### `sound_update` states (`sound_state` [0548], table `sound_table` [0559])

When sound is off (`editor_values[0]` = 0), `speaker_off` runs on every call: the pattern is 0,
and bits 0 and 1 are cleared.

| state | set by | handler | sound |
|---|---|---|---|
| 0 | default; each one-off handler returns here | 08D3 engine | Channel 2 and port 61h are set by `rpm_deficit` [1DCB] (below). The engine pattern is restarted from `engine_sound`, and channel 0 gets the RPM divisor (also patched into 07BC). |
| 1 | `flight_forces` (16B0) when angle of attack > 1F40h; also sets `stalled` [0558] = 1 | 0896 stall horn | While `stalled` ≠ 0, every call does `speaker_tone(05DCh)`: **795.5 Hz**, bits 0 and 1 set. Bit 1 is still toggled by the engine pattern, so the horn is chopped by the engine rhythm. When `stalled` = 0: state 0. |
| 3 | `war_guns` (3456), every frame of a burst | 08A9 guns | `spk_reload` = 0009h, `spk_restart` = 1, state 0 at once, channel 0 D = 12xxh. The next 6.07 Hz restart loads the gun pattern, unless the next `sound_update` (state 0) has already put `engine_sound` back. |
| 4 | `key_x_bomb` (0D45), with `bomb_whistle` [0540] = 64h | 08BE bomb | No output of its own. Channel 0 and port 61h are left alone while the bomb falls. When `bomb_state` [0575] = 0 (impact): state 0. |
| 8 | `flight_integrate` (1ABB) when `on_ground` changes (touchdown and lift-off) | 08CB click | `speaker_tone(0080h)`: **9.32 kHz**, bits 0 and 1 set, then state 0. It lasts until the next `sound_update`. |
| 2, 5, 6, 7 | never set | 08A4..08A8 | nothing |

**Bomb whistle** (`int8_timer`, 18.2 Hz part). While `bomb_state` ≠ 0:
`bomb_whistle` += 10 (at most 20000), then `speaker_tone(bomb_whistle)`. The frequency is
`1193182 / (100 + 10n)` after n ticks: 11.9 kHz at the drop, 5.97 kHz after 0.55 s, 1 kHz after
6.0 s, falling as 1/t. It is gated by the engine pattern like the horn.

**Engine roughness** (`rpm_deficit` = `rpm_windmill`[ias/16] − `rpm_by_power`[power] when the
airflow would turn the propeller faster than the power does, e.g. gliding at idle or with the
engine off):

| `rpm_deficit` (signed) | port 61h bits 0, 1 | channel 2 |
|---|---|---|
| 0 | cleared | 8080h (36.3 Hz), gated off |
| 1..19, or negative | set | **8080h: a 36.3 Hz square**, chopped by the pattern's bit 1 toggles |
| ≥ 20 | set | 0030h: 24.9 kHz, inaudible; the pattern pulses then switch between silence and that carrier |

**Not found in these routines:**
- a crash sound: a crash shows a message, and the engine noise follows `engine_sound` and
  `engine_rpm`;
- marker beacons;
- any other tone.

`speaker_tone` has only these callers: the stall horn, the touchdown click and the bomb whistle.
A channel 2 write also happens in `hook_int8`, set-up only: 8080h.

### A direct generator (sketch for 3.21)

The state comes straight from game memory (`gs_*` accessors) at each frame. Timing is in
seconds, not emulated cycles.

```c
typedef struct SoundGen {
    double t0;          /* phase within the current IRQ0 tick, 0..1 */
    double ff_phase;    /* 0..1 toward the next 6.07 Hz restart */
    double sq_phase;    /* channel 2 square phase */
    uint16_t pattern;   /* spk_pattern */
    int level;          /* port 61h bit 1 */
    double x1, y1;      /* DC blocker, as pc_speaker_render */
} SoundGen;

/* Per audio frame (n samples at rate), with a snapshot of the game state. */
void sound_generate(SoundGen *g, Pc *pc, float *out, int n, int rate)
{
    bool on = gs_editor_values_b(pc, 0);
    uint8_t st = gs_sound_state(pc);
    int a = gs_engine_rpm(pc) >> 2; if (a < 1) a = 1;
    double f0 = 1193182.0 / ((0x19 - a) * 256);               /* IRQ0 rate */
    uint16_t reload = gs_engine_sound(pc);                     /* A140h running, 0 stopped */
    if (st == 3) { reload = 0x0009; f0 = 1193182.0 / 0x1200; } /* guns */
    /* channel 2: gate (bit 0) and divisor */
    bool gate = false; unsigned div = 0x8080;
    int8_t def = (int8_t)gs_rpm_deficit(pc);
    if (st == 1 && gs_stalled(pc)) { gate = true; div = 0x05DC; }                  /* horn */
    else if (gs_bomb_state(pc))    { gate = true; div = gs_bomb_whistle(pc); }      /* whistle */
    else if (st == 8)              { gate = true; div = 0x0080; }                  /* click */
    else if (def != 0)             { gate = true; div = def >= 20 ? 0x0030 : 0x8080; }
    double f2 = 1193182.0 / (div ? div : 65536);
    for (int i = 0; i < n; i++) {
        if (!on) { out[i] = 0; continue; }
        g->t0 += f0 / rate;
        while (g->t0 >= 1.0) {                 /* one IRQ0 tick */
            g->t0 -= 1.0;
            if (g->pattern & 0x8000) g->level ^= 1;
            g->pattern = (uint16_t)(g->pattern << 1 | g->pattern >> 15);
        }
        g->ff_phase += 6.0681 / rate;          /* 1193182 / 65536 / 3 */
        if (g->ff_phase >= 1.0) { g->ff_phase -= 1.0; g->pattern = reload; }
        double x;
        if (gate && g->level) {                /* channel 2 square, gated by bit 1 */
            g->sq_phase = fmod(g->sq_phase + f2 / rate, 1.0);
            x = f2 > rate / 2.0 ? 0.0 : (g->sq_phase < 0.5 ? 1.0 : -1.0);
        } else {
            x = g->level ? 1.0 : -1.0;
        }
        double y = x - g->x1 + 0.995 * g->y1; /* DC blocker */
        g->x1 = x; g->y1 = y;
        out[i] = (float)(y * 0.2);
    }
}
```

What the sketch leaves out:
- **The `sound_update` level reset.** With `rpm_deficit` = 0 the level is forced low (and high
  otherwise) on each `sound_update` call. Call `g->level = def != 0` at the game's
  `sound_update` rate.
- **Bomb whistle stepping.** The whistle advances at 18.2 Hz. It can be computed from the
  bomb's fall time, as `div = 100 + 10 * ticks`.
- **One-off tones.** The gun pattern and the touchdown click last until the next
  `sound_update` call.

For 3.21, the simplest exact approach is to:
1. call a C version of these state transitions where `sound_update` and `int8_timer` run now;
2. have them emit (time, port 61h, channel 2 divisor, IRQ0 rate) events;
3. render the events with the loop above instead of `pc_speaker_render`.
