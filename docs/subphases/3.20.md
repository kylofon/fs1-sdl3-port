# 3.20 Scenery loading

Area file: `src/natives/sceneryload.c`. Cost table: `src/natives/sceneryload_cycles.h`, generated
by `tools/gen_sceneryload_cycles.py`. Sessions: `tools/scenery_sessions.py`.

## Natives

| name | address | campaign (`verify_campaign.py`) | area tour (`scenery_sessions.py verify`) |
|---|---|---|---|
| `select_scenery_area` | 03CA | 586 / 0 | 325 / 0 (config `all`, 16 area loads) |
| `scenery_load_loop` | 044E (copy loop of 03CA) | 0 / 0 | 16 / 0 (config `loop`) |

Counts are calls / mismatches. The original cost of an area change is 0.59–1.45 M cycles
(`original-cycles 203..1454509`); a call without a change costs 203 or more.

## How it works

- **The stream comes from the disk image.** Where the original fetches a stream byte from the
  track buffer (`mov al, es:[bx]` at 018C), the native reads that byte from the sector of
  `pc->disk` that the last read put there. The track is remembered from the INT 13h native; it is
  trusted only while `disk_track` = that track + 1 (what `boot_read_track` leaves after a good
  read). Otherwise (a failed read, a buffer filled by 3.16's preset load) the buffer itself is read,
  as the original does. `FS1_SCENERY_CHECK=1` logs any byte where the image and B800 disagree
  (none in any session; ATIS cannot draw during a load because `scenery_loading` = 1).
- **INT 13h in C.** The two INT 13h instructions do what pc.c's BIOS does: the 4 KB written to
  B800:0000 through `cpu_write8`, status in BDA 41h, AH, CF, and the INT frame (flags, CS, IP)
  left below SP. A hooked int 13h vector falls back to the CPU. Area 1–4 loads call the reset
  with DL = area index, so the BIOS returns status 80h there, exactly as with the original.
- **Every side effect is kept, none dropped.** The B800 track buffer (the last track of the area,
  on screen until the next blit), `stream_pos`, `disk_track`, `track_verify`, `screen_seg`,
  `disk_dx`, `disk_error`, the motor bits of BDA 3Fh (`and es:[043F], F0`, port 3F2h write),
  `cur_area`, `demo_ptr`, `demo_script`, `atis_idle`, `scenery_loading`, every register, the flags
  and the stack words of CALL / PUSH / INT. No `--verify` ignore ranges are used.
- **Method.** The original instructions (03CA–045C, 00EA–01AC) are transliterated on the emulated
  registers, one C case per address, with exact flags and the cpu8086.c cost of each instruction.
- **Interrupts.** A load spans several timer ticks. A call that is not under `--verify` (and not
  nested in a logging native) stops after the instruction in which the timer or the keyboard
  falls due (`irq_due`, as in 3.14/3.16/3.18), leaving the CPU at that boundary inside the
  original. The interrupt is delivered exactly where the original takes it; the original then runs
  at most the rest of one `boot_stream_byte` until the loop reaches 044E, where
  `scenery_load_loop` continues the load. A stop before an INT 13h reaches the INT natives, so no
  emulated INT 13h runs. All four entries share one interpreter, which runs until the entered
  routine returns.
- **No startup cache.** Reading the image directly at each load was simpler than a per-area cache.

## Other disk users

- **Preset save / load** (`s` / `l`): host file, 3.16.
- **`check_master_disk` (629C)**: already a 3.16 native. It reads track 1Ch through
  `boot_stream_byte`, whose track read now reaches `read_track_int13`.
- **Disk backup (5F54, 62D2, `disk_format_write_track` 00BE)**: stays original. It is only offered at
  the start-up menu with a master disk (track 1Ch byte 0 = 1, not the shipped image) and uses
  INT 13h AH=05/03 at 00E2 (format, write). Not reached in play.

**INT 13h use, measured** by logging pc.c's `bios_int13` in a local build (not committed), over
the three tour sessions: with the natives on, **0 BIOS INT 13h calls**, at boot or in play (the
boot loader's track reads also run `boot_read_track` at CS 0050, so they go through
`read_track_int13`). With the 3.20 natives off: 33–44 calls per session (boot plus one reset and
2–3 track reads per area change).

## Notes

- A keyboard latch falling due inside the three steps of an INT 13h (INT, stub, IRET) is latched
  after the IRET with the native instead of after the INT. This would shift the next key latch by
  36 cycles. It did not occur in any session.
- No framework change was needed. `symbols.txt` is unchanged: 044E, 00F5 and 0135 are entries inside
  existing routines.
