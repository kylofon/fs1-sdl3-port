## Cycles

The cost of each routine depends on its REP counts and branches, so a fixed `.cycles` cannot match it.
Each entry's `.cycles` is the fixed part of the original's cost, computed from the emulator's cycle
model (`cpu8086.c`). The native adds the variable part (10 per STOSW, 17 per MOVSW, branch differences)
to `cpu.cycles` itself. A temporary check in `verify_call` compared the native's total cost with the
original's measured cost on every call of every campaign session. There were no differences.
(This check was not committed.)

## Flags

None of the call sites test flags after these routines:
- `blit`/`clear` are followed by MOVs or calls.
- `fill_rows` is followed by a RET or a POP, or is tail-jumped from `draw_sky_ground`, whose caller does not test flags.
- `plot_pixel_es` returns into the scenery interpreter's loop (`xor ax,ax`) or into `pop bx`.

So `flag_mask` is 0 for all of them. The natives still leave the flags exactly as the original does:
- `clear_view_buffer`: from XOR DI,DI.
- `plot_pixel`: from the last OR AL.
- `fill_rows`: from OR CX,CX.
- `blit_view_to_screen`: unchanged.

## Formats and behaviour learned

- `clear_view_buffer`: ES = [3806] on return, CX = 0, DI = 2000h + 2·[3800], AX = [30C0]. Callers set
  [3800] first:
  - 0848h (2120 words = 106 rows) for the full view, in `radar_clear` (2ABC) and in the startup code at 5E1B.
  - 00A0h (160 words = 4 rows) in `slew_readout` (115A), which clears the top rows for the north/east
    readout before printing it. In the slew session this costs 3290 cycles.
- `blit_view_to_screen`: pushes and pops DS. The stack write is part of the comparison, so the native
  pushes too. On return: AX = ES = B800, CX = 0, DX = [3804], BP = [380A], SI = DI = [380A] + 2·[3804]. The setups are:
  - 4E6F: both banks full (0848h words from 0 and 2000h).
  - 4F21 (never executed): 07A8h words from 0140h and 07D0h from 20F0h.
  - 2AB0/5E27: counts only.
- `plot_pixel`: byte = row_offsets[y] + x/2.
  - Odd x replaces the low nibble with [30C8]; even x replaces the high nibble with [30C9]. The two colour bytes are pre-shifted.
  - x ≥ 128 still works, because the address uses a logical shift; only AH's SAR result is signed.
  - On return: BX = DX = byte offset, AL = new byte, AH = x SAR 1.
- `fill_rows`: for n = DL-BL+1 rows, it fills 40·ceil(n/2) words from row_offsets[BL], then 40·floor(n/2) from
  row_offsets[BL+1].
  - On return: AX = BP, BX = 2·BL+2, CX = 0, DX = the second bank's word count, SI = row_offsets[BL+1].
  - If n+1 were ≥ 128, the SAR would make the count negative. In practice n ≤ 106.

All the natives use the live DS and ES registers and honour DF, as the original does, even though no
caller has been seen with DF set.

## Screenshots

`--screenshot` output with all five natives on was compared with output using `--native-off` for each
of them. Views checked:
- regular flight, at 1200 and 3000 frames
- radar view (Num Lock)
- slew, at two points
- war mode

**The images are not byte-identical, but the scenes match.** The differences are small timeline shifts:
- a slightly different position on the runway
- the heading shows 000 or 359
- the clock is one second apart

The war screenshot at 4600 frames diverged further (a different sky band colour and gauges), as expected after 3000 frames of a diverged flight.

Tested one at a time:
- `clear_view_buffer`, `plot_pixel` and `plot_pixel_es` alone give identical screenshots in regular flight.
- `blit_view_to_screen` and `fill_rows` alone each change it.
- Two native-off runs are identical to each other.

**Cause (framework limitation, not a native bug).** A native call is a single `cpu_step`, so `pc_run`
delivers IRQs, and frame boundaries fall, only after the whole routine. The original's REP string
instructions are also single steps, but the blit has two of them, and there are instructions between them.

The full blit is about 72000 cycles. The timer IRQ is due every ~262000 cycles, so it often falls
inside the routine. It is then delivered up to ~36000 cycles later than in the original, and the
flight model's timing drifts. The cycle totals themselves are exact.

`--verify` shows that every call produces the same bytes and registers as the original from the same state.

**Suggested framework change (not made here; `native.c`/`pc.c` are off limits).** Let a long native
yield to the PC loop at the original's instruction boundaries: either charge cycles in segments with a
"deliver pending IRQ here" callback, or let the native return a resume IP. That would make bulk natives
timeline-identical. Without it, any native that replaces more than one long instruction shifts IRQ timing.

## Symbols (symbols.txt syntax)

```
var 0618:3802 blit_words0 word      ; [code] words blitted from blit_off0 (bank 0)
var 0618:3804 blit_words1 word      ; [code] words blitted from blit_off1 (bank 1)
var 0618:3808 blit_off0 word        ; [code] start offset of the first blit block
var 0618:380A blit_off1 word        ; [code] start offset of the second blit block (2000h bank)
```
